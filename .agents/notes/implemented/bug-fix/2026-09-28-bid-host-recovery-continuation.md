# Agent Note: Bid Host 持续恢复内部失败

Status: implemented

## Problem

S2～S5 的内部错误可能没有恢复元数据，或在 Run 收尾时直接变成 `failed`；未知校验码又默认阻断主 Agent。Goal 在 Session 重启时失去进程内授权，Host 重启的 Run 等待用户继续。目录修复回执会阻断新 Run，S4 锁定后也缺少客户可见总述的合法修正路径。

## Decision

Host 在 Run 收尾时用完整错误码集合识别确定的输入、权限、模型服务和数据安全阻断；其他 S2～S5 内部失败保留 `suspended` Run 与恢复诊断。短暂连接错误可以重试。资料映射优先保留结构化 `QUOTA`、`AUTH` 与 `NO_ADAPTER`，不因错误文本含 429 而降为可重试限流；限流任务共用 Provider 冷却截止时间，仍分别计算重试预算，持久化失败记录后只等待该截止时间。失败由[主 Agent 恢复工具](../architecture/2026-09-29-bid-goal-decoupling.md)分析和处理；Host 不代替主 Agent 决定修复方案。

Host 把遗留 running Run 持久化为 `suspended(host_restart)`，释放启动操作后按精确 Run ID 与项目 revision 调用原恢复入口，不依赖 Goal。能力 Work 在恢复准入前核对不可变请求的授权会话；其他会话的恢复被拒绝，不创建新 Run，也不改变原 Work。原 Executor 的检查点、输入指纹与提交栅栏决定能否续行；用户停止、等待输入和 S5 明确停止的写作入口不自动恢复。Goal 重激活由上述解耦决策替代；重复指令检查使用独立的 bid.recovery.requested 事件。

S2～S5 的 Host-owned Run 在兜底结算、后台目录交互、目录重生成、目录确认、章节修订和批量修订发生内部错误时保存结构化 recovery metadata。目录重生成候选返回失败也作为失败 Run 结算；错误码和结构化 issues 保留输入、权限及 Provider 的阻断分类。目录确认仍要求用户确认，主 Agent 只恢复已经授权的候选执行。

S3 的局部确定性修复每个 Run 至多一次，正式回执记录最近一次操作，不消耗后续 Run 的修复资格。S4 锁定子树仍拒绝结构和职责编辑，只允许当前任务范围内的 summary-only `update_section`；写入前检查客户可见内部编号，摘要变化不使 Structure Assessment 失效。

S4 Initial Mapping 只检查本任务可编辑子树的客户可见编号，避免其他任务范围内的总述问题阻断已完成章节；Final Check 仍检查完整目录。客户可见总述中的内部评分 ID 必须移除，正式 `scoring_ids` 和响应点绑定仍保留。

恢复中重新规划 `chapter.write` 时，Host 将原候选的身份、精确许可文件、文件哈希及删除记录冻结在计划补丁中。替代步骤保留或扩大原范围，新候选在 Run 提交权限内接收这些文件，S5 按当前契约重新核对并复用已完成正文审核。仅替换展示说明或重复修改待恢复计划也保留该来源；源文件不匹配时拒绝续行。`previous_targets` 的前一步结果不能代表完整拆章范围；省略原写作目标的补丁在保存前被拒绝。旧 Writer 的持久父子身份仍用于授权与清理，其当前模型选择来自本次执行 Agent，下一请求同时记录提示装配与模型路由。

写作候选前可插入仅修改业务绑定的 `outline.update`，使 Main 能纠正导致审核失败的职责归属。候选来源记录原步骤身份，插入步骤或再次重规划不改变来源；结构编辑、内容迁移、删除及省略原写作范围仍被拒绝。绑定修正通过正常能力校验后，恢复索引使用当前目录哈希和写作计划版本，保留原章节记录及正文；各章按当前输入身份核对，只有输入变化或审核未通过的章节重新执行。

同一用户消息先排队替代任务、再被原 Work 的计划补丁接纳时，计划补丁取消该消息的重复排队请求，命令日志保留 canceled 记录。队列调度在重启后同样核对原检查点的补丁授权，避免原 Work 完成后再启动重复任务；其他消息和会话的排队请求不受影响。

能力任务来源保存原消息之前、上次 Run 接纳或完成之后的真实用户消息及身份。用户先要求拆章、再补充章节名称时，计划和产物核验共同读取这些原话；模型计划不能补充授权。旧请求缺少上下文时按原消息序号从原会话重建，后来的消息不改变旧授权；已保存上下文与日志不符时拒绝执行。

原文迁移子会话使用结构化工具提交按源块位置索引的完整分配，Host 在工具提交前校验块覆盖、目标及关联块归属，使模型能在同一子会话修正漏块和表题分离。原生分配入口同样要求表题与完整表格、流程图引用与图锚点具有相同目标，并按原文顺序拼接。迁移结果包含源章子树全部可写叶节；没有迁移草稿的子章也进入写作审核。待迁移标记在写作入口阻断直接写作，写作指令不能替代迁移。

恢复来源可以是仅存在于当前候选目录的新子章，Host 按原授权父章的当前子树核对，不要求新子章已出现在拆分前的正式目录。已有正文的迁移目标也必须列入来源，防止原文分配覆盖未纳入的候选正文。后续写作和审核以原授权范围的正式正文识别只读块和原图，候选新增正文及图形仍可整改，避免把全部草稿冻结后无法修正重复和流程错误。计划准入要求未执行的写作排在迁移之后，恢复可以保留历史已完成步骤并补齐迁移。

原文只读块按正式源块的完整字节在候选中定位；即使新增文字与原文位于同一 Markdown 段落，原块仍被冻结。候选段落的解析边界不能决定原文是否受保护；未完整出现的原块仍由整项产物核验拒绝发布。独立 Reviewer 同时收到原图的只读身份，不能向 Writer 下达修改原图节点或连线的整改要求；既有交接节点由新增接口说明衔接，无法解决的业务冲突交由 Main 调整分配，新增图仍完整审核。

修复迁移同时读取原父章和已迁移子章时，正式原文的相同跨源章副本必须完整登记并具有同一个目标，Host 保留一次原文，不将副本合并视为删除授权。独有源块仍完整迁移；不同归属、漏块和真正删减仍被拒绝。模型分配工具与原生迁移使用相同校验，正式原文共享与发布次数受[原文单一目标决策](2026-10-04-bid-original-content-target-uniqueness.md)约束。

同一不可变请求首次计划核验通过后，后续核验只判断冻结要求是否由计划或产物满足，不再让模型重新判断授权。Host 继续核对原授权会话、原话、请求摘要、选区和实际文件范围。历史检查点若已有通过的计划授权，最新核验要求完全相同、全部业务检查通过且仅授权结论冲突，原会话的正常操作可将原失败 Run 收敛为可恢复状态；没有原授权、范围或产物检查失败时仍阻断。

章节 Reviewer 的任务分配冲突在没有外部资料缺口或必须由用户回答的审批意见时，作为能力计划的可修复错误交给 Main。非阻断的 `unresolved_topics` 保留在产物和诊断中；真实 `external_input_gaps` 仍等待输入。Main 在原 Work 改步骤指令或目标范围，保留成功候选后重新审核，不将职责冲突当作需要用户补资料。

章节日志的 completed 表示正文和合法审核报告已提交，不保证审核通过。局部写作恢复只保留输入身份有效且 verdict=pass 的章节；repair 和 attention 的原候选按当前计划重新审核，仍有正文问题时续写原 Writer。修订改变交接决策时重新编写强依赖下游，交接未变及无关通过章节继续复用。已迁移原表和原图属于产物保留约束，资料研究不能因正文不可登记为 Evidence 就认定这些载体尚未提供；项目事实的缺口仍由真实来源判断。

局部审核的恢复在正常候选验证中保留原 Writer 身份，正文、metadata、材料和输入摘要仍须一致；审核日志的 drafts 状态不撤销已接纳正文。隔离任务核验记录成功读取的证据区间，每个检查只绑定已完整读取且明确引用的文件；正文完成和原文保留的通过结论必须读取并引用范围内全部正文、metadata 与审核。未读文件或遗漏区间拒绝发布。

当前已发布结果收到真实用户纠正时，原 Main 只能在原 Work 追加步骤。Host 保留完成前缀和原发布凭据，按新授权保存补丁并恢复执行；追加步骤尚未重新发布时，旧凭据不能使新 Run 完成。完成通知按发布凭据摘要去重，同一 Work 的新发布保留新的 Run 通知，重复结算同一凭据不重复通知。原文范围绑定任务接纳时的章节身份；身份记录缺失时，正式目录或原首步骤候选的目录须匹配原输入摘要，候选身份同时核对原请求与步骤。候选中新生成并已发布的子章正文不成为额外只读原文。迁移输入同时提供原用户要求、冻结验收要求和当前分配指令，步骤说明不能缩减原目标。

## Alternatives considered

**只为已知校验码添加白名单。** 新 Validator 和子代理协议问题仍会被默认阻断，无法解决相同类别的后续故障。

**非模型执行器错误全部结算为 failed。** 缺失恢复元数据和模型协议错误会进入同一终态，主 Agent 无法分析真实诊断并改变处理办法；确定的外部与安全问题仍明确阻断。

**重复指纹或固定次数后停止。** 相同检查点不能证明新策略无效；原设计要求改变策略并沿用原生 Goal 总轮数，未新增 Bid 预算；当前由主 Agent 根据诊断决定下一步。

**让主 Agent 直接修改正式文件或重置阶段。** 这会绕过原 Executor 的局部范围、用户确认及 Run 提交栅栏。

**重新规划时丢弃原写作候选或只保留前一步目标。** 原候选已有通过审核的子章，重新开始会重复写作；迁移结果可能只列有原文的子章，不能据此省略尚未写作的新子章。

**只以最后一条用户消息核验授权。** “第5章也需要小章节”之后的“工作流程”是章节澄清，单独保存后一句会把明确的拆章要求误判为未授权。上下文来自真实事件及任务接纳边界，不依靠模型补写或关键词放行。

## Consequences

主 Agent 的错误分析仍可能需要外部修复代码；诊断和恢复指令留在 Session 中以供定位。Host 重启续行与主 Agent 修复复用同一项目锁和原 Work 检查点。测试覆盖混合错误分类、Host-owned Run 错误结算、精确 Run 续行、S3 新 Run 局部修复、S4 锁定摘要编辑，以及无 Goal 时主 Agent 接管并保留七个已完成任务。真实 Loader 回放覆盖部分新子章已完成后切换模型并重新规划：同一 Work 保留已完成正文和审核，只续写失败章节；定向测试另覆盖同输入计划补丁、连续补丁、遗漏目标及源文件哈希变化。

六子章 Loader 回放包含漏掉两个原文块、表题与表格分配到不同章、共享原文三次拒绝，模型在原分配子会话补齐后完成六章写作、审核，再修订候选新增正文后正式发布。原文只分给三个子章，其余子章没有迁移草稿，范围外正文及审核保持不变。
