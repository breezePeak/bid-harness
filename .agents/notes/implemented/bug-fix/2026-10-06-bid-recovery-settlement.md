# Agent Note: Bid 恢复必须执行并结算

Status: implemented

## Problem

失败通知、用户答案和执行结果具有不同含义。仅记录一次 Main 通知不能保证已授权任务继续；收到答案也不能证明恢复动作已应用。内部章节分工冲突、估页异常和用于退避的 Child 取消若丢失具体原因，会把可修复工作变成等待用户，或阻止原检查点续行。目录审查逐叶重复同级职责会放大输入，原样重试格式不能修复上下文超限。

## Decision

Main 判断业务原因、选择具体修复方案；Host 绑定原 Work、恢复 Run、请求与检查点，执行、持久化并核验结果。默认流程不依赖 Goal。`bid.recovery.round` 在主 Session 保存失败指纹、原目标、已安排轮数、有限预算、模型消息身份和结算；`bid.recovery.requested` 保存已接纳的语义策略。通知尚在 inbox 或真实回合尚未结束时不重复派发；回合结束后原失败仍存在且没有动作，Host 安排有退避的下一轮。恢复动作执行后仍有失败时必须调整策略；通过核验、等待真实输入、用户停止或预算耗尽均保存明确结算。

缺少用户业务选择或资料时，Main 使用原生 `ask_user_question` 等待回答；已有回答直接进入原任务的修复要求，不重复提问，也不以独立附件代替原任务续行。提问工具等待期间主回合保持未结束，纠正轮不追加执行；收到回答后仍须通过原业务入口执行并核验。S3 的未覆盖需求、评分及合规项由程序投影为当前输入位置与条款文字，避免把仅有内部编号的报错交给不包含编号的位置表猜测。后续准备事项可保留为全局合规要求，不虚构完成事实，不跳过正式校验。

纠正轮和原 Work 的执行恢复次数各受 `modelStageRepairAttempts` 限制，历史按原 Work 或已保存写作请求计数，不按新的 Run 或进程计数。同轮通知确认失败次数另行持久化且有有限上限，重试复用原消息身份；终止报告同样记录派发与消费事实。Host 重启从 Session 读取预算；到期唤醒重新检查 live 主会话、项目占用、当前失败与停止屏障。执行继续使用项目锁、原授权和既有 `resumeOf` 身份迁移，成功候选、正式正文、内容 Hash 与范围外成果保持原提交约束。

原生问题桥接保存稳定问题身份、答案和应用状态。答案只有持久化后才能作为 received 事实；继续动作仅在原恢复协议接纳后结算 applied。临时资源故障复用原答案，身份或版本无法证明一致时阻断，不猜测归属，也不要求用户重复同一授权。用户停止期间没有自动续行；新的明确继续请求仍经当前授权、版本与检查点校验。

Main 工具提问及 Execution 转交的提问把核对后的问题和真实回答保存为程序创建的用户消息，当前授权与任务来源读取同一事实。Execution 的普通提问在 Main 原生空间收集回答并返回原调用，不作为执行失败，不扣纠错预算；这部分替代[独立交互与执行通道](2026-09-14-bid-interaction-execution-lanes.md)中拒绝并终止后台提问的处理，双通道所有权及取消规则继续有效。整阶段正文的外部缺口保存原 Run 的 `awaiting_input`，复用输入应用日志，回答落盘后从原检查点续写；日志绑定本次答案的消息身份，章节问题详情与答案共同保存，不按其他任务的相同文本认领答案。旧 waiting_user 缺口按原阶段 Run 恢复此输入流程。

继续原 Work 时，执行上下文从原任务的用户消息和最近接纳方案重建；裸继续只提供此次接纳权限，不删除先前业务决定。相同问题按输入指纹、失败单元和错误项识别，候选 Hash 与普通进度变化保留独立检查点作用，不重置问题历史。

恢复授权的 instruction 保留接纳事件原文；重建的模型上下文与授权字段分开，S4 仍按原 Work、会话、事件序号和指令全文核对。模型上下文优先保留当前要求与本 Work 的最新真实回答，随后提供原请求及历史方案。单条完整输入超出预算时保留会话原文，由执行 Agent 及其运行时所属子任务的 `bid_read_recovery_input` 分页读取；独立子任务工具过滤器不撤销这个任务内读取能力，任务停止后读取失效。

Main 独立问题绑定原 live 会话和实际工具调用，不绑定后台阶段或最新 Run；Execution 问题绑定本操作的 Work 请求摘要与当前 Run，取消、替换或退役后拒绝晚到答案。`bid.user_input.recorded` 将答案消息关联到实际问题及可空的 Work 身份，同一问题重复保存复用原消息，其他 Work 或独立 Main 问答不混入当前恢复输入。

恢复预算和问题历史按 Work 累计，终态报告按具体 Run 和失败指纹消费。预算耗尽后，新的用户授权产生的新 Run 失败仍须唤醒空闲 Main；原 blocked 通知的消息身份与派发状态不能代替新 Run 的报告。重投与重启复用各自持久化消息身份，不重复报告，也不重置预算。

章节写作与修订按具体原因区分外部缺口和内部职责冲突。混合问题保留两类诊断，提问仅涉及外部资料。required 页数估算失败保留安全 cause 与错误码；真实不足保留审核报告，并在执行器及正式交付 Validator 拒绝完成。`preferred` 和只读审核报告保留独立结论。fast 估算使用现有格式计算，不依赖 LibreOffice。

S4 内部退避取消必须保留原网络故障，并与真实用户取消区分；用户取消优先约束竞态。执行日志保存首次基础设施预算及每次失败的模型或 Web 通道，检查点恢复据此还原已消耗次数；重启、换 Provider 或提高配置均不扩大原预算。目录全局审查使用共享职责索引和按完整输入估算的 token 预算，详细章节与跨片职责关系均有覆盖映射。上下文超限改变分片策略，不在相同输入上消耗格式修复次数；完整对象硬预算分段和旧本地预算 blocked 的恢复例外由[原任务恢复](2026-10-09-s4-review-partitions-and-legacy-recovery.md)拥有，有限预算与结算继续归本记录。

S4 已完成结构修复后的新恢复以会话及接纳事件序号关联下一代定向任务，重入复用同一任务组；审核从已保存采购来源装载原文，详见[定向修复与采购原文审核](2026-10-08-s4-authorized-repair-and-procurement-review.md)。

本决定部分替代[主流程与 Goal 独立](../architecture/2026-09-29-bid-goal-decoupling.md)中仅通知后由模型自主续行的机制、[持续恢复](2026-09-28-bid-host-recovery-continuation.md)中的无 Bid 预算取舍，以及[原生恢复决策](2026-09-15-bid-native-recovery-questions.md)中收到答案即抑制后续应用的机制。三份记录保留独立 Goal、原授权、候选保护、原生提问与历史事件的设计依据，继续保持活跃。

required 页数检查的执行异常与实际不足分别适用失败恢复和完成门禁，部分替代[页数结果校验](2026-09-10-bid-s5-live-chat-page-result-validation.md)与[建议性审查风险](2026-09-12-bid-s5-advisory-review-risk.md)中的完成规则；`preferred` 与只读审查的设计依据继续有效。[S2–S5 Goal 恢复](../feature/2026-09-23-bid-s2-s5-goal-recovery.md)及[校验失败交 Main 修复](2026-09-26-bid-validation-main-agent-recovery.md)保留其授权、范围和修复工具约束，续行调度与预算由本决定补充。

原任务失败后新的直接用户消息可授权一次继续，详见[用户继续授权](2026-10-16-bid-explicit-user-continuation.md)；这项授权不重置本记录的自动纠正预算。

## Alternatives considered

**仅在提示词中要求继续。** 文字承诺没有执行凭据，无法判断同一失败是否解除，也不能持久限制无动作回合。

**按新 Run 或进程重新计算预算。** 重启和合法身份迁移会重置次数，允许相同失败无限消耗资源。预算归原业务恢复链所有。

**收到答案后不再处理原问题。** 锁竞争、写盘故障和确认失败会留下已授权但未执行的动作；保存答案与应用结算必须独立。

**把 attention 全部询问用户，或把所有异常全部重试。** 内部分工应由 Main 修复，鉴权、配额、权限和身份错误也不能靠重复执行解决。具体原因决定恢复或等待语义。

**截断目录审查输入。** 会遗漏尾部章节或跨章冲突；分片仍需完整覆盖映射和全局关系检查。

**把恢复上下文写回授权指令，或沿用旧 Run 的已消费通知。** 前者使执行器无法核对真实接纳事件；后者会吞掉用户明确继续后的新失败。授权原文、模型上下文、Work 预算和 Run 通知各自使用已有记录中的对应身份。

## Consequences

恢复增加有限的模型纠正回合与有界审计事件，换取可追溯的实际执行和终止结算。上下文估算使用仓库 token-meter 的固定密度计量，不能替代 Provider 实际 tokenizer；超限仍须结构化拒绝或缩小分片。安全 cause 只保留有界错误码、消息、状态码和可重试标记，不保存 stack、凭证或原始 Provider 响应。

## Testing

定向测试先验证纯冲突、估页异常、网络取消与计划暂态失败的旧行为，再验证修复。真实 Host 和 Agent 配合 fake provider、真实临时目录与 JSONL 持久化，覆盖无 Goal 首轮仅文字、恢复执行、预算耗尽后重启、原 Run 迁移、原生答案复用、正式正文和 Hash 保留。Loader 应用回放验证业务提问先于恢复、等待期间不启动新 Run，答案进入模型上下文后继续原任务；S3 定向测试验证缺项使用当前条款位置，并保留后续演示要求。真实模型身份绑定验收同时移除响应点与合规关联，验证修复后均恢复并通过原 Validator。fake provider 的协议和故障验证不代表真实模型语义质量。

原生回答回放覆盖自动预算耗尽后无需额外“继续”消息即可启动原 Work。真实模型 A02-native-answer 从自然语言任务自行提问，答案直接冻结为任务来源，随后完成目录拆分、原文迁移、正文编写和独立审核。正文输入回归覆盖已消费计划的旧 waiting_user、答案落盘后重启、相同文本的跨任务消息隔离及完成章节复用；Loader 回放从新主会话接管的 suspended 项目读取原 Run，验证回答进入真实章节研究、只生成缺口章节并保留已完成正文。后台连续业务提问不产生失败或恢复扣次。
