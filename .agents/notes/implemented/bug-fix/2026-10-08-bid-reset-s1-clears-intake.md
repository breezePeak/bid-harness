# Agent Note: S1 重置清空项目资料

Status: implemented

## Problem

Bid 用户在同一项目回到 S1，是为了重新上传一批资料。保留上一轮上传文件、解析语料和清单，会让下一批资料继续混入旧内容，无法得到空白上传入口。

## Decision

Bid Preset 注册无参数 `/bid-reset-s1`，调用已有 `resetStage(agent, 'file_intake')`。Host 在项目锁内取消并等待执行静止，再用同一项目事务清空 `input`、`corpus`、`manifest.json`、项目 Word 模板与格式配置，以及分析、目录、正文、私有工作目录和导出产物。项目状态保存为 `file_intake / waiting_user / run: null`，不创建 Execution Agent 或自动驱动；下一批上传从空清单开始。

删除范围限于当前项目管理的资料副本和产物。项目外的原文件、聊天历史、项目注册与内置 Word 模板资源保留。其他阶段重置继续保留 S1 资料；取消、并发及后续阶段清理由[中断恢复与阶段重置](2026-09-01-bid-interrupted-stage-recovery.md)拥有。

S1 上传面板以成功的重置命令节点清空浏览器文件选择和旧反馈，重新读取模板库与能力计划。重置与切换会话使旧上传请求失效，迟到响应和进度不能恢复模板或继续上一批资料上传。普通能力完成和重连也可能产生同阶段、同状态的新任务投影，因此仅凭任务对象变化不能清空尚未上传的选择。已重置历史能力任务的请求文件不存在时，计划接口返回空结果；活动任务缺失请求、请求身份不符与其他读取失败仍报错。

## Alternatives considered

**保留已上传资料供下一轮复用。** 资料复用可以减少上传，但与 S1 重新开始的用户意图冲突，也会使新旧资料混合；S1 重置明确清空资料，复用由其他阶段重置保留。

**新增专用 Host 方法或 Remote。** 现有阶段重置已拥有取消、项目锁、产物清理和持久化；另一条入口会重复这些规则。固定命令让用户无需新建项目即可回到上传入口，Host 继续拒绝未来阶段和带参数命令。

**删除整个项目目录。** 项目进度、聊天和项目外文件不属于资料重置；按现有项目事务删除各阶段拥有的文件，保留这些对象。

## Consequences

用户需要重新上传资料和项目 Word 模板，阶段派生成果需要重新生成。命令单测、Host 重置测试和真实源码 Loader 快照验证命令分派、等待状态、资料与产物清理、外部原文件保留，以及重新上传不会混入旧资料；S2 重置仍保留上传资料。面板回归验证同 S1 重置后的模板库、文件选择与旧反馈清空，以及普通任务更新和重连保留待上传选择；能力任务回归验证已删除历史请求返回空计划，指纹校验仍拒绝损坏请求。
