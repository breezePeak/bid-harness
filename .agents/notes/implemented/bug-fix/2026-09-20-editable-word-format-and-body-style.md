# Agent Note: 可编辑 Word 格式与正文样式归属

Status: implemented

## Problem

Word 格式页只允许用户在未确认差异的证据候选中选择；差异一经确认，主要格式表变为只读，无法纠正模板识别结果或按本次投标调整格式。页面把当前模板内部多个候选的差异称为“格式冲突”，容易被理解为模板与系统默认格式不一致。章节 Writer 没有稳定收到“仅段落第一句为总结句时加粗”的明确边界，可能把局部强调要求扩大为整段或全文加粗。

## Decision

每个主要格式角色始终提供“修改”入口。编辑器从当前 `resolved` 值开始，提交该角色的受校验字段并合并到完整 `userConfirmed`；用户覆盖可以取任意字段 Schema 接受的值，不限于模板证据候选，也可在保存后继续修改。`revision` 继续拒绝并发旧写入，预览和导出继续只读取同一份 `resolved`，磁盘状态版本不变。

页面把 `conflicts` 投影为“当前模板内格式差异”。差异比较排除 `system_default`、docDefaults、Theme 和既有用户覆盖；系统默认值只补充模板没有定义的字段，不会因为与模板值不同而制造待确认项。候选选择框仍用于解释当前模板内的 Named Style、直接格式和模板正文说明差异。

S5 Writer 任务明确区分语义加粗与模板排版：段落第一句话只有在概括本段结论、总体措施或核心安排时才加粗，并且只加粗这一句；普通开场句、后续展开句、整段、多句、列表、表格和全文不统一加粗。Reviewer 按同一语义边界检查候选并要求原 Writer 修复滥用。提交边界保留 Markdown `strong`，因为程序无法可靠判断一句话是否具有总结性质。标题及普通正文的字体、字号和字重继续由 Word 模板和用户格式覆盖决定。

## Alternatives considered

**确认后只提供“重新解析模板”。** 不采用；用户只是调整一个已识别字段时，重新上传和模型解释会增加无关工作，也不能表达本次投标的明确覆盖。

**继续限制用户只能选择证据候选。** 不采用；模板解析证据用于给出可靠初值和解释差异，不应阻止用户设置合法的交付格式。

**禁止或导出时移除所有 Markdown 粗体。** 不采用；这会删除用户要求的段首总结句强调，静默改写还会掩盖正文与已审核候选的差异。

**用确定性校验判断总结句。** 不采用；是否属于本段结论、总体措施或核心安排依赖正文语义，标点或位置规则不能可靠替代 Writer 和 Reviewer 的判断。

## Consequences

格式确认不再是不可逆状态，用户可以纠正正文是否加粗、字体、字号、行距、缩进及同一角色的其他受支持字段。内部 `conflicts` 字段和状态枚举为现有磁盘格式保留，用户界面只使用准确的格式差异用语。新生成或修订的叶节正文可以保留段首总结句加粗，但不得扩大到后续句、整段或全文；已有已保存正文不会在读取或导出时被静默重写。
