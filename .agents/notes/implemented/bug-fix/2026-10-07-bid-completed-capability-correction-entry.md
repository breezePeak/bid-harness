# Agent Note: 已完成能力在原阶段继续纠正

Status: implemented

## Problem

独立能力完成后恢复任务前的阶段状态；原阶段可能是 ready、waiting_user 或 completed。只在 completed 状态开放纠正工具会让同一个已发布 Work 因整本路线的等待位置而无法继续。追加补丁改变步骤总数，重复调用若按新总数判定起点，会再次追加并执行相同步骤。

## Decision

纠正入口核对同一能力 Run 的启动、完成和最后通知，允许三种稳定任务前状态。完成通知不能替代完成事件；后续原生阶段记录也不能充当能力身份。真正失败的恢复使用失败通知所指向的启动记录。Host 仍在项目锁内验证原发布凭据、当前文件、授权会话、任务范围和检查点，只允许对已完成 Work 追加纠正步骤。

工具在读取检查点前捕获当前授权，计划补丁按同一消息、标准化步骤、原起点和补丁结果长度识别重复提交。重复提交保留已接纳前缀、历史凭据、当前项目状态和执行预算。不同的新消息仍形成新的授权，不能仅按业务文字去重。局部能力恢复 ready 后，Main 空闲不会自动启动整本阶段；原生写作入口明确接纳已有计划时仍可启动。

能力计划摘要优先使用当前 Run 的运行或挂起状态；完成状态同时要求本 Run 的完成事件和当前检查点全部步骤已完成，导出尾步骤由正式导出回执结算。旧完成事件和发布记录不能掩盖追加后的待执行步骤。

本决策补充[能力步骤与发布](../architecture/2026-09-24-bid-capability-task-work.md)和[能力重规划](2026-09-29-bid-capability-replanning.md)的已完成任务入口与补丁幂等条件。原授权范围、停止、等待真实输入、不可恢复失败、候选检查和正式发布规则继续有效。

## Alternatives considered

**把项目状态改为 completed 来开放工具。** 独立任务不能替整本路线确认阶段，纠正入口应依据能力完成事实。

**纠正时创建新 Work。** 会丢失原任务核验链并重复执行已完成能力，原 Work 的检查点与发布凭据应连续保留。

**对相同步骤永久去重。** 后续独立用户消息可能明确要求再次执行；只有同一授权的同一补丁可复用。

## Consequences

三种任务前状态使用相同的纠正行为，代价是入口同时依赖能力事件关系和持久发布凭据。真实 Host 测试覆盖同 Work 追加、重复提交、恢复原阶段及范围外文件不变；事件测试覆盖缺少完成、错误通知、用户停止、等待输入与阶段不一致的拒绝。源码 Loader 回放覆盖真实 Main Agent 接收后续用户消息并通过公开工具纠正。
