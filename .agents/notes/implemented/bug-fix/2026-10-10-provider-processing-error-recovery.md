# Agent Note: 服务端处理失败分类与旧 Work 恢复

Status: implemented

## Problem

pi-ai 的流内失败可能只保留错误文本。服务端明确提示处理失败且允许重试时，缺少 HTTP 状态码使适配器保存 `PI_AI_ERROR`，Bid 随后把原 Work 永久 blocked。只修正适配器不能解除已保存的旧失败。

## Decision

LLM 共享错误模块仅识别同时包含服务端处理失败和允许重试的完整诊断，适配器将其归为 `SERVER`。Bid 对旧 `PI_AI_ERROR` 使用同一识别器计算有效分类，保持原始错误、Work 身份、恢复历史和剩余次数。任一其他阻断优先拒绝；历史终止仅在原因与当前误分类一致且次数尚未耗尽时重新开放，已接纳恢复后的新 Run 沿用同一预算。

原 S4 预算耗尽后，新的直接用户目标可通过现有候选接管入口建立独立 Work。手动接管准入复用共享恢复分类，接受 `repair` 和 `retry`，不按某一历史错误文本单独开放工具；自动恢复次数不限制新的直接授权。接管仍要求失败候选、已完成检查点及完整来源可核验；新授权与原 Run、项目版本绑定，旧预算不重置，其他真实阻断不开放该入口。

[S4 后续恢复链](2026-10-10-s4-review-output-budget-and-recovery-chain.md)仍拥有旧输入预算、输出超限及检查点核验；[恢复结算](2026-10-06-bid-recovery-settlement.md)仍拥有有限派发和终止通知。这些规则保留活跃，本记录补充错误分类，没有替代它们。

## Alternatives considered

**重试全部未知错误。** 无法区分永久故障，会反复提交无效请求；仅允许已识别的暂态诊断。

**清空状态或用无授权的新 Work 绕过次数。** 会丢失原授权、恢复预算和候选关系；恢复和新目标接管均须经过原会话的正式工具，旧次数与候选关系保留。

## Consequences

提供方仍可能持续失败，有限预算耗尽后明确终止。适配器、恢复资格及真实 Loader 会话回放覆盖旧 blocked、其他阻断优先、预算耗尽、原研究保留和正式确认；未知错误仍不可自动恢复。
