# Agent Note: 运行中保留已输入消息的发送入口

Status: implemented

## Problem

普通会话运行期间，输入框允许编辑和按回车排队，但主按钮始终显示为停止。用户输入追问后只能依赖不明显的键盘行为，容易误判为消息无法发送。鼠标发送和章节引用还会丢失键盘策略选择，继续未完成任务也会降级为排队。

## Decision

空草稿继续使用主按钮停止当前运行；草稿非空时将发送设为主按钮，并在旁边保留独立停止按钮。鼠标发送复用普通 Enter 的 `resolveSubmitMode`，服务、业务提交处理器和 Bid 章节引用继续传递已选的 `queue`/`steer` 与取消信号；恢复未完成任务由 DSH 原生用户提问处理，不再借用普通消息的 `steer`。这样不改变 Host 的队列与 steer 策略，也不让发送动作取消当前运行。

## Alternatives considered

**继续把发送放在次要入口。** 不采用；已输入内容缺少明确的鼠标发送入口会让用户误以为输入框不可用。

**让非空草稿仍触发停止。** 不采用；会丢失用户已经输入的追问，并把发送与取消混为同一操作。

## Consequences

运行中的普通会话可以通过按钮提交已输入的追问，同时仍可单独停止当前运行；现有回车、队列和子 Agent 行为保持不变。省略服务参数仍使用 `queue`，章节引用发送失败时仍保留引用且不回退为第二条普通消息。
