# Agent Note: 运行中聊天的本地交接与 Host 后台阶段交互

Status: implemented

## Problem

普通聊天提交与输入框、引用准备和 Host 受理共用一个提交锁，慢请求会阻止后续输入；阶段交互工具在交互 Agent 的工具回合内等待长任务，导致主任务占用聊天响应并使生命周期清理提前发生的风险重新出现。

## Decision

普通消息在输入机捕获文本、引用和附件身份后立即完成本地交接，输入机只为命令路径保留同步事务锁；每条普通提交使用独立客户端身份和 Session-owned outgoing 记录，Host 正式 `user/message` 通过同一身份接替本地行。Host 队列仍是投递事实来源，outgoing 仅用于展示准备、提交、排队、投递、送达未知和失败状态；接受回执不再伪装成正式消息已送达，断链状态保留原内容等待重连事件。

S4/S3 长阶段交互在完成准入、创建 Run、取得 Execution Agent 后立即返回已接管结果；后台任务继续持有 Run、Execution Agent、项目锁和收尾责任，只有真实完成才发布用户确认状态，失败或停止则结算为挂起。

## Alternatives considered

**继续依赖单个 `inflight` 和回执后清空草稿。** 否决：任何慢引用、附件或受理请求都会把新草稿与旧请求重新耦合。

**只在 QueueDock 中维护本地 pending 数组。** 否决：切换会话、重挂载和正式消息交接会产生第二套事实来源；本地记录必须由 Session 持有并由聊天快照投影。

**删除长工具调用中的 `await`。** 否决：原有 `finally` 会在后台任务仍运行时释放 Run、锁和执行器；后台生命周期必须明确接管完整收尾。

## Consequences

输入框释放与 Host 受理解耦，迟到回执不能覆盖新草稿；本地 outgoing 行必须等到同身份正式消息、明确失败或用户逐行放弃后消失。客户端协议增加可选 `clientSubmissionId`，旧调用方省略时由 Host 生成兼容身份。阶段工具返回“已接管”不代表产物完成，结果、失败和停止继续通过现有 Run 状态及会话事件发布。普通会话的唯一 Stop RPC 同时触发 Bid Host 的 Run 停止收敛，因此主 Agent 已空闲时也不会遗留后台阶段任务。
