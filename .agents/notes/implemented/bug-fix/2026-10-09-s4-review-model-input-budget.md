# Agent Note: S4 目录审核的模型硬上限与分片目标

Status: implemented

## Problem

目录审核把 12,000 token 分片目标同时作为单个请求的拒绝上限。完整采购原文和单章资料达到 15,496 token 时，即使当前模型仍有足够上下文，已完成的章节研究也会在独立目录复核前失败。

## Decision

目录复核从当前 Provider/Model 的容量扣除系统 Header、工具、输出和安全余量，得到输入硬上限；未知容量保留 16,384 token 的保守估计。常规分片目标为 12,000 token，并受硬上限约束。超过目标的完整单章独立请求，单索引及片间配对按实际硬上限接纳。公共依据占满目标时，索引分组仍保留最多半个目标的增量空间，且完整请求不越过硬上限；完整索引能放入该空间时只做一次共享关系审核，避免公共原文迫使每章索引单独分片。程序保留全部原文、每章详细审查和所有跨片职责关系；真实超限的处理由[硬预算分段与旧任务恢复](2026-10-09-s4-review-partitions-and-legacy-recovery.md)拥有，本记录保留容量推导和完整对象优先的理由。

Provider 实际返回上下文溢出时，分片目标与硬上限同时缩减，按缩小后的预算重新构造请求。意见整理先尝试目标预算，超限时只保留所属详细卡片和必要职责索引，并按硬上限接纳；实际溢出且输入无法继续变化时保留原错误，不重复调用相同请求。

本记录补充[采购原文审核](2026-10-08-s4-authorized-repair-and-procurement-review.md)的预算判定；来源身份、完整原文和恢复授权仍由该记录约束。[分片终审](../architecture/2026-09-14-s4-sharded-final-review-and-session-authority.md)继续拥有 Final Check 任务、检查点和 Main Session 权限，两份记录均保留活跃。

## Alternatives considered

**统一增大固定阈值或取消分片。** 输入会随目录及来源增长，固定阈值不能体现模型差异，整书请求还会增加无关上下文；常规分片目标应独立于模型容量。

**截断原文或拆开单章卡片。** 审核可能丢失决定性采购条件，分散的章节判断也不能替代完整职责审查。模型能容纳完整对象时，独立请求保留其语义范围。

## Consequences

大章与共享采购原文可以使用更多上下文，输入费用按实际请求增加；普通小片保持原目标。模型容量未知或 Provider 容量声明错误仍可能导致明确超限失败，不以截断证据或重做研究掩盖。生产项目磁盘格式和检查点身份保持不变。

## Testing

分片回归固定完整原文、单章独立接纳、硬上限精确边界和所有跨章关系；执行器入口验证不同模型容量的完整接纳与无损分段。真实 Loader 的 S4 会话回放覆盖大原文独立审核、跨章复核和正式 Evidence Map 发布；真实 API 原文复核包含超分片目标场景，缺少凭证时该验证跳过。
