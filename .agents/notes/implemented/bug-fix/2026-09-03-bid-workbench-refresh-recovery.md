# Agent Note: Bid 工作台刷新恢复

Status: implemented

## Problem

工作台将所有 Remote 失败显示为 `BID_REVIEW_NOT_ALLOWED`，且成功刷新后保留旧错误。阶段卡片也会在 Host 已推进流程后显示上一阶段迟到的操作错误。阶段切换、后端重启和并发刷新会让已恢复的页面继续显示旧错误，旧请求还可能覆盖新结果。

## Decision

工作台复用现有 `actionFailure` 保留 Host 错误码和消息。自动轮询等待上次请求结束再计时，避免慢请求被连续轮询挤掉。组件以请求序号协调刷新和章节选择，阶段切换或卸载使在途结果失效；只有当前请求可以更新正文或错误。阶段卡片在 Host projection 的阶段或状态变化时清除上一操作的旧错误并使在途操作失效，文件接入的部分失败继续保留。成功刷新清除旧错误，无可读正文时清空旧选择与正文。

## Alternatives considered

**只替换通用错误文案。** 这仍会让迟到请求覆盖新阶段，并在成功刷新后保留旧错误，不能恢复页面状态。

**依赖取消底层 Remote 请求。** 组件不能保证已发出的请求在 Host 推进阶段后立即终止；请求序号可以在响应到达时统一拒绝过期结果。

## Consequences

Host 继续决定阶段权限，客户端不修改阶段状态、不忽略当前请求失败。组件测试覆盖失败后的刷新恢复、阶段推进以及较早请求的迟到错误。
