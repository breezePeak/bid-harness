# Agent Note: S1 文档解析与失败结算

Status: implemented

## Problem

DOCX 图片先编码为 base64 HTML、再由正文转换器丢弃，会把图片密集文档放大到数亿字符并导致正则转换栈溢出。S1 校验失败若携带值为 `undefined` 的恢复字段，严格 JSON 会话日志拒绝保存终态；文件清单虽已记录失败，项目仍停在运行中。失败后的上传准入也必须允许用户更换材料。

## Decision

`extractDocument()` 的 DOCX 转换器直接跳过图片，不读取媒体字节，只保留标题、列表、表格和正文；原 DOCX 完整保存在 `input/`。阶段校验失败只在存在恢复信息时提交 `recovery` 字段，S1、S6 的失败状态仍满足会话日志的无损 JSON 要求。S1 的失败终态开放上传，执行器直接接纳该阶段的新批次；后续阶段的失败准入保持各自恢复规则。

同一内容、同一资料类型解析并分块成功后，发布清单删除该身份在导入前已有的失败条目，成功条目置于同身份不可用条目前；原始文件和旧语料文件均保留。文件 ID 由内容 SHA256 决定，失败条目排在成功条目前会让按 ID 查找的语料引用先命中失败记录。文件名分配同时读取清单与 `input/` 的存量名称，防止已移出清单的原件被同名上传覆盖。本批次的每个文件结果和不同资料类型仍分别保存，成功记录不会被后续解析失败替代。

本决定补充[统一语料提取](../feature/2026-08-28-bid-corpus-document-intake.md)的图片读取策略及[上传批次完整性](2026-09-01-file-intake-batch-completeness.md)的失败结算。两份记录分别保留统一解析入口、跨格式取舍和完整选中文件集合的校验依据，未被本决定替代。

## Alternatives considered

**提高内存或正则栈预算。** 图片编码不参与语料结果，增加资源预算仍承担无用媒体读取及字符串扩张，不能消除输入规模触发的转换失败。

**在日志层丢弃 `undefined`。** 会隐藏生产者提交非法状态的问题，并削弱所有会话事件的无损 JSON 校验；应由构造失败状态的执行器省略不存在的字段。

**失败后要求重建项目。** 原始输入和已保存清单仍有价值，新的 S1 批次可在同一项目校验，不需要删除项目或重置后续阶段。

## Consequences

正文语料不包含 DOCX 图片，原文件保留图片供其他明确需要媒体的能力使用。解析错误保存为失败终态，项目锁释放后可重新上传。真实 DOCX 测试观察 ZIP 读取以证明媒体未解压；真实 Host 持久化测试和无密钥 Loader 回放固定失败终态及再次上传。真实工作区的失败后重解析验证成功清单及 S4 语料引用，原始字节保持完整。
