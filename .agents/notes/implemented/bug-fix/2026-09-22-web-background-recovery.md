# Agent Note: 浏览器前台恢复与连接消费者重启

Status: implemented

## Problem

浏览器切回前台时，下行连接可能仍表现为打开却不再交付消息。仅在流结束后重连会让后台完成的回复停留在服务端，用户只能等待或刷新。S4 运行中有独立的进度查询和会话消息流，进度请求成功不能证明会话流仍然正常。

开发环境的运行模块热更新还会卸载页面根节点。连接服务的消费者停止流后必须释放占用；否则新运行模块调用 `start()` 会被拒绝，依赖它的页面无法重新挂载。排查中已观察到现有 URL 的根容器为空、标题恢复默认值，而同一服务的新页面正常。

## Decision

连接服务将流循环和浏览器恢复监听归入同一个可释放 effect。当前消费者停止后释放占用，重复停止旧消费者不影响新消费者。隐藏或失焦后的首次前台恢复重建两条流，`focus` 与 `visibilitychange` 共享恢复标记；在线事件也触发重连。会话沿用现有历史补读流程，恢复不刷新页面、不重发用户消息。

连接循环取消当前代时退出握手、流等待或退避；迟到的旧代响应和帧不能交付给新代。WebSocket 读取在取消时立即结束本地迭代并丢弃缓冲帧，不把浏览器的网络关闭握手当作本地读取结束的条件。

快照通知使用本轮订阅者快照；回调中的重订阅从下一轮生效，避免遍历活动 `Set` 时反复执行同一个回调。单个回调异常会记录并隔离。S4 正常进度同步只使用计划表头，独立错误提示及已有进度保留。

## Alternatives considered

**每次切回刷新整页。** 刷新会丢失输入和局部交互状态，也无法修复消费者占用未释放的问题；连接重建可以复用会话补读。

**仅增加 S4 进度轮询。** 进度查询不负责聊天消息流，也不能重新激活热更新后失败的运行模块。

**等待 WebSocket 自行关闭。** 浏览器后台暂停和半开连接没有可靠的及时关闭保证，本地取消必须独立完成。

## Consequences

前台恢复增加一次连接握手和会话补读，换取下行停滞后的可恢复性。页面监听随消费者一起释放，不累积多个恢复循环。单元测试固定消费者重启、取消和订阅重入行为；真实 Web 组合测试在 S4 运行中发送消息并暂停下行交付，验证返回后无需刷新显示回复、侧栏、输入框和计划。
