# Agent Note: 自动预算耗尽后的用户继续授权

Status: implemented

## Problem

阶段失败后，自动纠正达到次数上限会撤下恢复工具。用户随后明确要求继续时，S2 和 S3 没有可执行入口，主 Agent 只能重复失败诊断；将有限自动恢复当作永久禁止继续，会使保留的原任务和候选无法使用。

## Decision

S2–S5 可修复或可重试的失败 Run 公开已有 `bid_resume_current_run`。模型理解用户语义并选择继续原任务，程序从当前会话绑定 Run 和项目 revision，在项目锁内核对新的直接用户消息晚于原失败通知，再通过原 Executor 恢复同一 Work。模型不提交消息身份、Run 身份或次数。

一次消息只授权一次继续；再次失败后，同一消息、自动通知、Goal 轮次及历史授权不能追加执行。恢复要求和尝试继续写入已有会话事件，不清空历史、提高上限或建立替代 Work。原输入、候选、业务范围、归属会话和正式提交校验继续生效；权限、凭据、输入过期等真实阻断仍拒绝。

本决定部分补充[恢复结算](2026-10-06-bid-recovery-settlement.md)和[原 Work 持续恢复](2026-09-28-bid-host-recovery-continuation.md)：自动纠正仍有限，新的人类请求拥有独立的一次执行授权。两份记录继续拥有自动预算、终止结算、检查点和候选保护，不归档。S4 的新目标接管仍适用[独立补修 Work](2026-10-10-s4-review-output-budget-and-recovery-chain.md)，继续原目标不创建新 Work。

## Alternatives considered

**清空次数或提高自动恢复预算。** 会抹去已消耗的恢复记录，并允许无效自动回合持续运行；用户新授权只增加一次实际执行。

**新建 Work 或重置阶段。** 继续原目标需要保留候选和已完成检查点，替代身份与清理产物扩大了修改范围。

**仅提示模型再次尝试。** 工具缺失和执行入口的预算拒绝仍存在，必须在实际 Host 接纳时核验新的直接用户消息。

## Consequences

用户可在自动预算耗尽后主动继续，也可能再次遭遇相同业务失败。继续接纳只表示执行已开始，最终结果仍由阶段提交与校验决定。定向回归验证旧消息、自动通知、同一消息重复调用及真实阻断拒绝；源码 Loader 回放固定三次耗尽后的用户消息、实际工具调用、原 Work 身份、恢复关系和保留的预算。
