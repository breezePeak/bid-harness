# Agent Note: S4 进度读取保持项目投影一致

Status: implemented

## Problem

S4 的浏览器轮询可能携带落后的 Session 投影，而 Host 只从调用会话读取运行状态，导致已保存的挂起进度被误判为不可读。前端读取失败或终态后停止轮询时还会清空最后一次有效进度，并把执行日志中的未结算任务显示成仍在运行。

## Decision

S4 进度 Remote 在每次读取前以同项目的活动 Bid 操作或最新项目检查点为权威来源，最多重试三次稳定取样；发现调用会话或浏览器观察值落后时，只通过已有 `bid.project.resumed` 事件重发权威快照，观察值不参与写回。Host 返回 `null` 时不改变项目执行状态，且保留不带观察值的一参调用方式。

Bid 面板按主会话、阶段、状态和 `workId` 维护最后一次成功进度，轮询请求串行化，并在运行中、挂起、失败和等待确认状态持续重试。请求失败或暂时没有进度时保留同一工作身份的卡片；切换会话或工作身份时丢弃旧缓存。取消收尾和进度同步失败显示为警告，历史 `running` 任务在非运行状态显示为未结算或待恢复。

## Alternatives considered

**让浏览器观察值覆盖 Host 状态。** 不采用。浏览器投影可能已经过时，写回它会把挂起、Run 身份或工作身份恢复成错误值。

**只在 UI 保留上一次进度。** 不采用。UI 缓存只能避免视觉闪烁，无法修复调用会话与项目检查点之间的身份错位，因此 Host 必须先校准权威投影。

**根据主 Agent 是否忙碌推断 S4 状态。** 不采用。聊天 Agent 的忙闲区间不等于 Host 执行 Run 的生命周期，状态仍由项目控制状态和 Run 原始状态决定。

## Consequences

落后的页面第一次读取可能只完成投影校准并返回 `null`，随后由已有投影通道交付相同身份的状态；页面在此期间保留最后有效卡片。短暂的读取错误不再伪造失败或清除进度，但错误会通过状态条和辅助文案可见。S4 日志、Run 协调和通用投影存储不需要新增状态或兼容路径。

## Verification

`project-session.spec.ts` 覆盖更新项目检查点校准落后 Session 且不启动新 Run；`bid-stage-panel.client.spec.tsx` 保持现有 S4 轮询和状态展示回归。Host 构建及两组指定 Vitest 测试通过。
