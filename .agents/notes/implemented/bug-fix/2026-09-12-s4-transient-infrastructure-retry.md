# Agent Note: S4 限流基础设施错误自动恢复

Status: implemented

## Problem

S4 Mapping Child 遇到请求限流时，执行器把一次可恢复的 Provider 错误提升为整个阶段失败，并中止尚未开始的章节任务。项目随后只能显示人工重试，已启动任务的上下文和任务队列也无法由 Host 自动收敛。

## Decision

S4 Host 对 Mapping Child 的基础设施错误区分可恢复限流与不可重试错误。具有 `RATE_LIMIT`、非账户额度耗尽的 HTTP 429，或明确表示 RPM 限流的失败，在单个 Mapping Task 范围内按有限指数退避自动重新创建 Child；Provider 提供的 `Retry-After` 延迟优先，默认延迟从 500 毫秒开始并限制在 60 秒内。默认最多自动重试两次。

自动恢复期间任务日志保持 `running`，其他章节继续使用已有并发槽位；重试成功后继续原批次，任务不显示为失败。自动预算耗尽、账户额度耗尽、模型输出无效或 Host 持久化异常仍按原规则终止批次并进入阶段失败，用户重试入口只处理这些最终失败。

Mapping Child 的 `turn/end` 错误保留稳定 code、status 和 Provider 重试延迟，Host 据此分类，不从普通用户可见文本推测账户额度。未接受结果不能再通过空映射结果伪装成已完成任务。

## Alternatives considered

**让用户看到失败后手动点击重试。** 不采用。429 是服务端要求稍后再试的暂时状态，恢复责任属于当前 S4 Host；人工入口只应处理自动预算耗尽或不可恢复故障。

**任一限流都重启整个 S4 批次。** 不采用。已完成的章节和仍可运行的兄弟任务不需要丢弃，按单个 Mapping Task 重试可以保留检查点并减少重复模型调用。

**无限等待并持续重试。** 不采用。Provider 或账户额度可能永久不可用；有限预算保证阶段最终能进入明确失败状态，并保留现有人工重试入口。

## Consequences

限流恢复不再把未开始章节错误地标记为失败，S4 页面在恢复期间保持运行态，成功后继续目录生成与资料映射。自动重试会重新创建受影响章节的 Child，因此不会复用已失败回合的模型输出；同一 Child 内的语义修复预算与本次基础设施重试预算彼此独立。测试覆盖限流首次失败后的自动恢复、重试日志、最终任务计数，以及永久基础设施失败不得伪装成完成。
