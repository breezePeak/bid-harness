# Agent Note: 原 Work 的有限恢复窗口与安全清理

Status: implemented

## Problem

章节模型错误在 Child 返回、抛出和外层包装之间丢失分类，暂态故障可能消耗内容修复次数，鉴权阻断也可能被机械重试。嵌套计数放大正文执行量；只按 Work 历史累计的恢复限制则忽略新验收成果，使一次用户继续只能推进一轮。等待期限晚于无限 await，清理期限又不能作为旧写入失效的证明。

## Decision

章节 Writer 和段落修订保留有界安全 code、message、cause、状态码与可重试标记。已分类的返回失败和直接异常共用恢复分类，外层包装不覆盖原身份；没有结构化原因的错误使用稳定未知故障。鉴权、额度、权限、输入和真实容量限制优先阻断；暂态模型故障使用追加执行余额，候选或审核问题使用内容修复余额。两种余额分别消费，章节内基础设施余额不随正文修复、会话重建或视觉回传恢复。正文执行、Reviewer 请求、视觉确认和底层请求重试各自计量。

已审核而未正式发布的章节候选保存在原 execution-log，绑定原 Writer、Reviewer、输入与候选摘要。恢复重新核对计划、epoch、证据、来源和审核关系，保持原 Writer 归属并复核候选；旧父会话使用现有恢复器按项目身份恢复。基础设施失败不发布未完成 manifest，也不把 repair 审核变成 pass；正式提交成功才删除临时候选。每个失败章节暂存完整候选会增加执行日志大小，换取不重写已审成果。

纯后台失败通知使用 bid_recover_task；独立能力任务可先用 bid_plan_task 调整未完成步骤，保留完成前缀。bid_resume_current_run 仍要求当前有效授权。完整模型上下文明确用户本轮意图优先：状态问答不执行，停止不被失败通知覆盖，新目标使用既有目标变更入口。公开工具的真实 guard 保持有效，工具列表不按消息临时重装。用户停止已失败的原 Run 时仍持久化 user_stop，保留原 Work 与故障，已落盘但尚未确认交付的恢复通知重新核对停止边界后不再唤醒 Main。

bid.run.progress 的 checkpoint 只由 Host 在验收并落盘后记录，包含单元、输入和计划身份；Run 记录将其绑定到原 Work 与不可变请求。普通进度不构成证明，同一单元在原 Work 内最多刷新一次窗口。窗口从 Session 历史推导，重读、重复事件、新 Run、重启和文案变化不产生额度；问题 fingerprint 继续承担同错识别，候选变化不能代替进度证明。

modelStageRepairAttempts 默认三次，分别限制每窗口恢复执行、连续无有效动作的纠正通知和同轮派发确认重试。接受真实恢复动作后无动作计数重新开始，执行用量仍累计。recoveryTotalAttempts 默认九次，即最多三个默认窗口的基础执行额度；无新进展时仍在首个三次窗口停止。新的直接用户继续消息只开启一次有限窗口，并追加该窗口的累计额度；该次恢复也计入窗口。接纳事件保存两个上限和原消息，重放与并发通过原接纳操作去重，配置提高不扩大已记录的基础累计额度。旧 blocked 只约束其窗口，权限、输入、版本、停止与等待输入的限制不被窗口覆盖。

每个 S4 首次 Child 和 follow-up 在进入 whenIdle 前启动总期限；默认三十分钟，部署可通过 runChildTimeoutMs 调整。超时取消原 Child，并保留 TIMEOUT。runCleanupTimeoutMs 默认一分钟，按资源报告 S4 finally、settlement checkpoint、main、children、activities、commits 和 execution handle dispose 的阻断。期限只产生诊断，仍等待资源实际静止：关闭调度、退休新 lease 并排空已接纳正式写入后才释放项目。清理拒绝或无法证明旧资源静止时保持写入阻断，不以 Promise.race 开放新 Run。

S4 输出耗尽保持实际输出 cap，强制复用无损分组程序细分字段和原文；输入预算同步缩小，最多两次调整，全部请求保留完整目录树及跨章关系审核。已通过片仅在完整请求指纹一致时复用。最小请求仍不能完整输出时保留候选并以独立输出预算错误阻断，不重复相同配置。用户修正部署后可明确继续原 Work，不把 contextWindow 或默认请求 cap 当作可自由提高的输出能力。

本记录部分替代[恢复结算](2026-10-06-bid-recovery-settlement.md)的单一 Work 次数上限、[用户继续授权](2026-10-16-bid-explicit-user-continuation.md)的一次执行额度及[输出预算](2026-10-10-s4-review-output-budget-and-recovery-chain.md)的直接停止策略。三份记录仍分别拥有通知与输入结算、当前消息接纳和输出容量推导的独立约束，保留活跃；[无损分段](2026-10-09-s4-review-partitions-and-legacy-recovery.md)继续拥有覆盖与来源规则，无归档记录变更。

失败身份、双份章节成果、合并通知核验与 Reviewer 启动事务的生命周期关联见[恢复断点](2026-11-06-bid-recovery-lifecycle-breakpoints.md)。

## Alternatives considered

**放大一个累计常量或清空历史。** 前者不能区分真实进展与空转，后者使重启和重复消息获得无限额度。窗口与累计上限同时从既有日志推导，旧用量保持可审计。

**只修提示或撤销授权 guard。** 提示必须与完整模型上下文和实际工具一致，当前消息授权仍由 Host 执行入口验证，通知不能伪装用户继续。

**清理超时立即释放锁或仅在异步写入开始前检查 epoch。** 已接纳写入仍可能晚到，无法证明最终发布安全；实际 drain 是开放新写入的必要条件。

**提高 maxTokens 或截断审核输入。** 默认请求 cap 不证明模型输出能力，截断又破坏原文和跨章覆盖；缩小可独立验收单元保持部署限制和原候选。

## Consequences

无进展的恢复仍有界，新验收成果和明确用户继续可在累计限制内推进原目标。清理无法完成时项目保持占用，用户得到资源诊断，需要旧资源真正退出后才能恢复写入。回归覆盖真实 Child 错误链、交替预算、同消息去重、窗口与累计上限、首轮及后续永久等待、延迟 lease、Loader 完整上下文与无密钥会话回放；外部模型语义和真实提供方通道仍需有凭证的 e2e。
