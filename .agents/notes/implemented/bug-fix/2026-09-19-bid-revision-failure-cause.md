# Agent Note: 保留批量修订的底层失败原因

Status: implemented

## Problem

批量章节修订失败后，Writer 已写入批次任务的具体错误，但结算阶段再次把任务失败信息替换为笼统的“章节执行失败”，用户无法判断是会话恢复、模型输出还是章节校验导致失败。

## Decision

批量修订结算优先保留任务 artifact 中已经持久化的失败详情；只有旧批次没有详情时，才使用章节执行日志生成 `SECTION_FAILED` 回退错误。任务状态仍按章节日志收敛，错误原因不再被后续结算覆盖。

## Alternatives considered

**只修改界面文案。** 不采纳，因为界面没有可用的底层错误信息，修改展示文字无法恢复已丢失的诊断原因。

**在每个 Writer 失败路径重复写入用户提示。** 不采纳，因为批次任务 artifact 已是章节执行与结算之间的权威状态，重复生成错误会扩大状态同步面。

## Consequences

批量修订失败记录现在会显示 Writer 或校验阶段的具体错误，旧批次仍能通过 `SECTION_FAILED` 回退信息读取。回归测试覆盖失败详情在重复状态结算中的保留行为。
