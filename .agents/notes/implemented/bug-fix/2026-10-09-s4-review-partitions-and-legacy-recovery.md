# Agent Note: S4 硬预算分段与旧 blocked 原任务恢复

Status: implemented

## Problem

单章审查包包含完整业务依据和采购原文，超过模型实际输入容量时，仅减少每批章节数不能缩小输入。旧本地 12,000 token 拒绝还被保存为服务商上下文错误及 blocked，重启后恢复入口仍拒绝原目标。完整目录和映射诊断会触发工具结果溢出，主 Agent 无法仅通过公开查询工具取得失败原因。

## Decision

完整单章优先使用模型硬预算；真正超限时按章节关联业务项、结构差异、实际操作和原文分段。字段路径、来源身份及 UTF-16 字符范围由程序生成，字符串分段保留全部内容和代理对。每片只允许判断实际提供的依据；全部请求成功后才接纳完整审核。详细卡片核对业务与原文，共享职责索引逐对核对章节关系。单章节意见整理使用同一分组程序，避免合并时重新携带无关全书数据。最小请求仍超限使用独立本地预算错误；服务商真实溢出继续采用有界缩减和相同输入拒绝。

只有 `stage_execution/evidence_mapping` 且诊断完整匹配旧固定 12,000 token 本地组包错误的失败，才能重新计算 blocked 恢复资格；其他阻断、停止和等待输入保持原限制。原 round、持久预算、失败指纹、项目锁和输入身份仍有效，不清空日志。执行器在启动子任务前核对原日志、研究检查点和目录候选；有效 completed 研究复用，缺失或不匹配明确失败。恢复沿用原 Work，新的 Run 记录 resumeOf，审核和正式确认仍由现有流程完成。

状态摘要和恢复诊断只返回有界失败、可用动作、阶段及完成数量，不附加完整目录、映射或对象表。详细对象通过现有项目查询分页选择。公开工具和失败提示使用同一恢复资格，接纳不等于产物发布；初始研究、最终检查和 Evidence Map 分别报告。

本决定替代[模型硬上限与分片目标](2026-10-09-s4-review-model-input-budget.md)中真实超限直接失败的选择；该记录仍拥有容量推导与完整对象优先的理由。[采购原文审核](2026-10-08-s4-authorized-repair-and-procurement-review.md)仍拥有来源核验和结构修复授权，[分片终审](../architecture/2026-09-14-s4-sharded-final-review-and-session-authority.md)仍拥有 Final Check 与检查点。[恢复结算](2026-10-06-bid-recovery-settlement.md)仍拥有有限预算与通知结算。以上记录部分职责延续，保留活跃。

## Alternatives considered

**放开全部 blocked 或重置研究。** 前者绕过真实权限、输入和凭证故障，后者丢失原目标及可复用检查点；恢复例外必须由明确历史诊断和实际候选证明约束。

**截断原文、压缩为摘要或让模型口头分批。** 决定性条款可能在尾部，模型不能证明未收到的依据；分段及完整覆盖必须由程序构造。

**增加临时文件读取工具或新诊断存储。** 查询协议已有分页，短摘要足以选路；新增协议不能解决摘要本身复制完整对象的问题。

## Consequences

大原文可能增加独立审核请求和跨章配对成本，但不重做有效研究。未知模型容量保守估计，最小请求无法容纳时仍失败。旧会话恢复要求原磁盘候选与检查点有效；仅有会话日志不能证明用户本机项目可恢复。

## Testing

预算边界、业务与原文分段重建、代理对、意见整理和中途失败验证完整覆盖及发布时序。25 个 completed 研究检查点验证无重跑。真实 Host 重启验证持久 blocked、模型实际工具与提示、输入变化、缺失检查点、候选差异、审核发布及用户确认；大目录查询验证有效 JSON、返回体积和详细对象分页。真实 Loader 无密钥快照覆盖大原文独立审核、硬预算分段和现有结构恢复；真实采购原文 API 复核在有凭证时运行。
