# Agent Note: S4 恢复授权绑定修复代次与采购原文审核

Status: implemented

## Problem

完成的研究和结构修复检查点只能证明历史动作完成，不能证明新恢复目标已经处理。以计划中存在修复任务阻止再次修改，会让后续恢复只复核同一候选。独立审核如果仅有规范化业务摘要，也不能据此判断采购原文没有某项事实或任务。

## Decision

S4 以已接纳 `bid.recovery.requested` 所在会话及事件序号标识恢复授权，任务计划保存该关联，程序按最后持久化结构问题的章节身份建立下一代局部修复。相同授权重入复用任务组和检查点，不再创建代次；不同授权分别生成任务身份。已完成研究和范围外结果保留。修复任务、动态新叶与后续审核共享已接纳指令、待关闭问题及程序计算的候选变化摘要。

授权预算继续归原 Work 所有。新 Run、取消后的续跑及重启不创建新预算；接纳回执只表示请求已接纳，执行回执按实际产物变化区分修改与仅复核。预算耗尽不改盘或退款；新的直接用户消息可通过 `bid_run_task(supersede=true)` 接纳独立 S4 补修 Work，冻结并复制原失败候选，以标准执行器、审核和校验发布结果。完整任务计划保存到新 Work，仅接纳项目范围的单步目录深化或允许深化的补充研究，多步任务在创建 Work 前拒绝。续跑仍要求原授权主会话；已完成检查点丢失或指纹失效时明确失败，不退回初始研究。

审核从 S2 `source_refs` 定位已上传采购文件的 Corpus 和 Chunk，核对文件角色、解析状态、所属路径、索引身份和行范围后装载完整原文。项目事实、业务原文和来源归属随审核卡片提供；同一文件 Chunk 去重，并随现有 token 预算分片。单个完整原文放不下时明确失败，不截断决定性证据。缺失或错挂来源先阻断补证，不生成“采购没有依据”的结论；摘要与原文冲突由审核保留诊断并按原文纠正。

本决定补充[恢复执行与结算](2026-10-06-bid-recovery-settlement.md)和[主题归位与锁定](2026-09-11-s4-topic-disposition-outline-lock.md)。两者仍分别拥有原 Work 预算、Main 调度、结构判断和局部编辑权限，保留活跃。[程序身份绑定](2026-10-05-bid-host-id-bindings.md)继续拥有模型入口位置协议，并规定任务与计划互斥、来源搜索与读取用途。

## Alternatives considered

**仅移除历史修复判断，或按每次执行递增代次。** 前者会复用同名旧检查点，后者会在取消和重启后重复创建任务；任务组必须绑定已持久化授权。

**清空研究、重新 S1 上传或扩大重试预算。** 完成的研究与采购文件仍有效，实际缺口是定向修改没有执行；扩大范围和预算无法补足动作链路。

**把 Project 摘要视为最终事实，或只添加审核提示。** 摘要仍可能遗漏或误述采购条款，审核必须得到真实文件归属和完整原文；身份与路径合法也不代替语义核验。

## Consequences

来源失效会在 Reviewer 启动前明确失败；采购原文增加输入成本，现有分片预算仍覆盖完整输出。恢复任务增加一个可选授权关联，历史任务及内部组合操作保持可读取，当前模型入口只接受互斥任务更新或完整计划提交。程序保证身份、权限和实际执行凭据，模型仍负责职责、依据关联和业务事实的判断。

## Testing

完成 checkpoint 回归先复现旧执行器没有新修改 Child，再验证新代次、取消重入、同指令不同授权、范围外保留和修改后审核输入。实际注册工具验证混交被 Schema 和直接入口拒绝、合法两步提交及已发位置；原文审核入口覆盖摘要遗漏、摘要与原文冲突、文件错挂、缺失 Chunk、非法范围及完整原文超预算。真实 Loader 会话覆盖 Host 接纳恢复到定向修改和复核的链路，以及耗尽预算后新任务接管、原会话续跑、历史授权和损坏候选拒绝；无密钥回放验证协议与持久化，不代替实际采购项目的语义验收。
