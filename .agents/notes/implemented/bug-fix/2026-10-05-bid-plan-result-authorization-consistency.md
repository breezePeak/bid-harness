# Agent Note: Bid 规划与产物核验共用真实授权

Status: implemented

## Problem

用户要求第八章增加小章节，再用数字选择助手提供的章名。任务来源只保存用户消息，核验模型看不到数字对应的选项，还把用户没有说过的“仅改目录、不授权迁移、正文及审核”加入要求。首次核验接受包含这些步骤的计划，最终核验又用同一限制拒绝已经完成的步骤。完成前缀不能撤销，追加和删除未开始后缀都不能修正这条矛盾；内部错误保存为挂起使正常任务反复停住。

## Decision

Host 从任务接纳前的原会话事件绑定用户与助手的公开文本，助手选项只解释用户短回复，不构成授权。原消息、用户上下文和已保存对话均按原序号核对；后来消息不能扩充旧任务的权限。来源、计划和产物核验使用相同对话。

语义要求用 `source_quote` 逐字引用真实用户要求或意见，Host 用原话保存描述，不接纳模型改写的权限摘要。明确禁止能力单独保存为 `scope_constraints`，每项绑定真实来源和逐字原话；模型计划、助手选项及不存在的原话不能作为禁止项。没有明确限制时，拆章计划可包含维持原文可用的迁移、补全和独立审核。Host 在计划和产物两个入口拒绝包含禁止能力的步骤，不能让冲突计划先执行。限制在第一次接纳后固定，结果核验只能判断产物和原要求，不重新解释已接纳步骤的授权。范围外字节、选区、真实新节点和当前写作规则仍由原校验拒绝非法输入。

核验记录保存完整来源摘要；只有摘要与当前绑定来源相同且每项要求有原话证明的通过记录才能冻结要求或复用结论。缺少这项证明的通过和拒绝记录保留为审计，不传入新核验的历史判断。原 Work 用原消息重建对话并重新核验计划，不改不可变请求、不复制任务、不跳过结果核验。

未获删除授权的 `chapter.reorganize` 默认保护正式原文块和流程图定义；最终核验逐字、逐图检查唯一性，不依赖模型是否把保留义务写入要求。Host 从已完成写作步骤收集实际目标，最终检查这些目标的当前写作身份和通过审核，步骤完成不能代替正文通过，范围外未写作章节不扩大为本任务验收目标。

Writer 的原图集合按已分配的正式原文锚点从正式来源取回完整定义，不以候选图是否仍与原定义相同判断其保留义务。误改或缺失的候选原图仍受保护；同名原图存在不同正式定义时须由当前匹配定义确定身份，不能静默选择另一章的图。新增图只在不同锚点下独立整改。

完成通知以正式收据的 `goal_met=true` 描述本次任务范围内的最终核验，不把修复前步骤的审核摘要当成当前状态，也不把局部任务完成声称为全书验收通过。步骤历史保留在原检查点供审计。

执行器错误和修复预算耗尽先排空 Run，再提交带诊断的 `failed` 状态，内部执行问题不产生 `bid.run.suspended`。主 Agent 自动接管可修复问题；Host 从同一会话最后开始的 Run 和严格对应的失败通知恢复身份，普通阶段编排与能力任务共用 `bidRecoverableRun`，不在阶段恢复层重复要求任务为 `suspended`。计划补丁、候选检查和恢复仍使用同一 Work、原请求及已完成前缀。输入、权限及模型通道阻断保留明确失败原因，不假报完成；用户主动停止、真实等待输入及重启续行仍遵守各自控制规则。本项结算规则部分替代[Host 持续恢复](2026-09-28-bid-host-recovery-continuation.md)的内部错误挂起实现，保留其恢复所有权、范围和候选复用决策。

## Alternatives considered

**把未提及正文解释为禁止正文。** 沉默不是禁止授权，不能由验收临时创造执行限制；明确只改目录的原话仍必须拒绝写作步骤。

**忽略最终拒绝或把任务状态改成完成。** 目录、正文、当前规则和独立审核可能确有问题，仍需完整证据和正式发布收据。

**只把挂起改成失败，丢弃恢复身份。** 无法继续已完成前缀，用户仍被迫重建任务；恢复身份必须来自原会话的失败通知，而不是模型抄写的 Work ID。

## Consequences

同一任务只有一个可发布成果，写作和验收使用固定要求。定向回归覆盖数字章名选择、捏造禁止原话、首次计划违反明确限制、产物阶段增加限制，以及内部失败保留原 Run 供自动修复。源码 Loader 回放在同一核验子会话拒绝捏造限制，完成真实目录节点、原文迁移、写作、审核及发布；故障恢复回放核对同一 Work、完成前缀和范围外正文保持有效。
