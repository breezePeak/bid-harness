# Agent Note: S3 响应点确定性派生与目录局部续修

Status: implemented

## Problem

目录生成要求模型同时抄写 RP 编号、文本快照和所属评分项，容易出现引用与快照错配。遗漏响应点后全量重生成又会改变稳定编号和无关章节，丢失已经有效的目录成果；质量报告中的全量已检查编号也不能单独证明当前目录版本完成过语义复核。

## Decision

正式响应点清单在 S3 中途由 Host 分配稳定编号。响应点分析使用一个无文件工具的 Child structured output，Host 把当前 Scoring 直接注入 Prompt，并要求 Child 在同轮完成语义自检。Host 用 Candidate Schema 校验返回值，再校验评分归属、每项至少一点与连续顺序；通过后才向当前 Run 暂存目录写入 Candidate 并生成正式清单，非法返回不创建新 Candidate，也不覆盖已有合法 Candidate。目录生成、质量复核及局部修复任务继续接收正式清单的准确路径和完整数据。正式清单不是 S3 启动前置输入，稳定身份的理由沿用[持久化目录与响应点](2026-09-01-bid-persistent-outline-response-points.md)，响应点写入边界由[结构化响应点与流式参数熔断](2026-09-20-s3-structured-response-points-and-tool-argument-fuse.md)记录，有界恢复规则见[S3 有界执行与 Artifact 恢复](2026-09-21-s3-bounded-outline-generation-recovery.md)。

模型只选择章节的 scoring_response_point_ids。候选 Schema 允许省略派生快照；Host 根据正式清单重建快照并合并所属 scoring_ids，保留合法独立评分关联，去重后进入正式 Schema 与既有基础校验。未知编号报错，不从评分项反推全部 RP，不修改章节结构或写作内容。正式目录的字段与版本保持不变。目录候选的生成、质量复核与局部修复仍按当前 Agent 作用域解析 read 与 write；read 的 limit 超过部署上限时使用工具默认窗口重试，write 包装器移除与会话当前模式相同的冗余 sandbox_permissions 和配对 justification 后交给原工具执行。真正更高的升级请求仍沿用原审批与严格升级检查。

Host 计算未被可写叶子覆盖的差集，将 RP 原文、所属评分原文和当前目录交给模型。RP 专用修复使用现有 update_section、add_section 和 split_section 操作，并显式提交最终 RP 选择和具体 must_answer；Host 分配新章节编号并应用操作。需求、合规、框架和结构错误使用 S3 专用关联操作，接收相应原文及合法框架标题路径；浏览器编辑 Schema 不获得这些权限。将已拆分的父节改为结构章时，模型在同一 repair_structure 操作中显式清空父节 must_answer，子节保留各自作答要求；Host 根据 parent_id 派生 level，未知父节点和环仍由结构校验拒绝。资格材料等全局 Compliance 不会因缺少可写页而分配给技术叶子。操作在副本上应用，规范化和校验后保存，不允许引入非法引用或结构；有效进展保留，剩余覆盖继续在同一预算内处理。语义归属仍由模型判断，不用章节数量、位置或关键词代替。

初稿、质量复核修改和失败恢复共用候选解析入口。Schema 与规范化问题携带文件、字段路径及章节标识；字段操作只能修改问题定位的顶层或章节字段，不接受任意 JSON 路径或整章替换。未知 RP、评分关联必须由模型明确重新选择合法 ID，并保留已有合法关联。JSON 语法失败使用独立候选文件，Host 保留原文并检查所有字符串、数值和字面值的原文与顺序；无法仅修正序列化标点和空白时明确失败，不借此重新生成目录。格式修复和确定性修复各至多一次，确定性修复与回执原子发布；恢复时根据回执拒绝再次修复。

质量复核覆盖 Host 明确提供的当前完整目录和招标输入。全局资格、证书及行政递交事项由 global_compliance_ids 覆盖，质量复核不得仅因没有可写页而新建章节。结构父节只用 summary 概述且 must_answer 为空，具体作答由可写叶节承担。质量复核修改 RP 归属时在同一操作中提交完整的章节 must_answer，Host 拒绝缺失写作指导的局部操作。模型在唯一一次完整复核中直接修正阻断问题、自检修改结果，并通过执行期私有工具提交结构化 advisory issues，不写质量候选文件。工具漏交只允许一次没有目录写权限的协议续行；Host 对本轮复核后的目录重新规范化和确定性校验，再生成 v4 正式报告及完整 checked_* 和 reviewed_section_ids。失败、取消和未经复核的改动不能发布正式报告。该直连边界的取舍见[模型与 Host 复核直连边界](2026-09-09-bid-model-host-review-boundaries.md)。

outline/generation-inputs.json 绑定本轮启动输入内容。输入版本未变化时复用有效正式清单及目录候选，从规范化或剩余局部修复继续；输入改变、正式输入损坏或清单不匹配当前评分时返回输入错误并保留产物，必须通过阶段重置更新正式输入，不能由模型改写清单来消除候选错误。用户确认文件不属于模型可写路径，正常重试不能覆盖已有 S3 确认版本。目录生成总体职责仍由[蓝图生成](../feature/2026-08-30-bid-outline-generation-agent-stage.md)记录。

## Alternatives considered

**删去缺失校验或自动挂到任意章节。** 编号出现不代表章节能够实际回答评分要求，因此保留可写叶子覆盖和语义复核。

**让模型重写全书并同步抄写所有派生字段。** 这会扩大局部错误的修改范围，并引入重复抄写错配；派生字段由正式清单确定，语义决定通过局部操作提交。

**输入出现过的编号直接算已复核。** 输入交接只界定复核范围，不能证明完成；只有该版本的正常复核结果才能生成正式已检查清单。

## Consequences

S3 失败恢复保留编号、有效目录、修复回执和已完成质量报告，成功仍停在用户确认；S4 资料映射和 S5 正文读取继续使用原有正式目录结构。质量复核修改目录不再触发第二轮完整复核，模型必须在唯一一次复核内自检，Host 随后只执行确定性校验。无密钥 Loader 会话验证有界编排与持久化协议，不替代真实模型语义质量评估。
