# Agent Note: 正文轮询不废弃手动章节选择

Status: implemented

## Problem

正文工作台在 S5 写作期间每秒刷新目录和当前章节。轮询与点击章节共用请求版本号；用户点击后，下一次轮询会使尚未返回的章节读取失效，页面只能等待轮询再次读取该章。正文较多或 Host 忙时，这种竞争使切换显得长时间无响应。

## Decision

工作台分别跟踪目录刷新和手动章节选择。目录刷新仅淘汰旧目录结果；手动选择及历史对比会淘汰更早的章节结果。目录刷新开始后若用户切换章节，迟到的轮询不覆盖选择，也不丢弃用户请求。会话卸载或切换时废弃未完成的手动章节读取。

## Alternatives considered

**延长轮询间隔。** 只能降低竞争概率，并延迟 Writer 和 Reviewer 状态展示，无法保证点击请求有效。

**缓存全部章节正文。** 正文和审核在写作期间变化，维护缓存一致性会增加状态和失效规则；当前按需读取已经满足切换需要。

## Consequences

用户点击已写章节后，随后开始的轮询不会迫使章节重新读取。目录和章节仍按原频率取得 Host 最新结果；Host 读取或网络本身的耗时仍会影响首次显示。组件回归测试固定“点击章节后轮询开始、章节请求随后返回”的顺序。
