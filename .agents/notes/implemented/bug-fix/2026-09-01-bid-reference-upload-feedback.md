# Agent Note: 标书参考文件缺少招标文件时的上传反馈

Status: implemented

## Problem

标书面板允许选择参考旧标书，但上传按钮只在批次包含招标文件时可用。用户单独选择旧标书后看不到可执行的失败提示，文件只停留在浏览器内存中，也不会进入当前 Session 的 `input/` 目录。

## Decision

上传按钮在至少选择一个文件时保持可点击；上传操作在客户端先检查批次是否包含 `tender` 文件。缺少招标文件时显示明确提示并保留已选文件，用户补选招标文件后可一次性提交。Host 仍负责最终校验，且一个成功的文件接入批次必须包含成功解析的招标文件。

## Alternatives considered

**继续禁用上传按钮。** 这隐藏了失败原因，用户无法区分“尚未选择文件”和“缺少招标文件”。

**允许仅上传参考旧标书并由 Host 接受。** S2 需要招标文件作为当前项目事实来源；放宽 Host 会产生没有权威招标输入的无效 Session。

**选择文件后立即写入 Session。** 这改变了当前“明确点击上传并解析后才持久化”的行为，并会使未提交的浏览器选择进入工作区。

## Consequences

参考旧标书仍需和至少一个招标文件一起提交，但缺少招标文件时用户会收到可操作的错误信息，且无需重新选择旧标书。已提交文件继续保存在当前 Session 的 `.bid-harness/sessions/<session>/input/`，而不是项目根目录的 `input/`。
