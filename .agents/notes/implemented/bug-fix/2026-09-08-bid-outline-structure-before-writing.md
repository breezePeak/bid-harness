# Agent Note: S4 先对照完整目录，S5 按叶节写作

Status: implemented

## Problem

按关键词命中的旧标正文可以说明某项工作，却不能代表原文的章节组织。目录深化只扩充 must_answer 和写作维度时，背景、实施步骤和质量措施会挤在同一叶节；正文随后自建下级标题，即使覆盖检查通过，用户确认的目录也无法表达成稿结构。只有当前章节任务的 Writer 和 Reviewer 还可能把错放的任务当成必须展开的内容。

## Decision

S4 正文定位、任务用途及检查点 v3 遵循[材料用途与职责复核](../feature/2026-09-08-s4-material-purpose-review.md)；本记录保留完整目录输入与 S5 叶节标题约束的取舍。

S4 在派发业务分支前读取旧标及用户原始框架的完整标题结构，将其与本次候选目录及章节职责一并交给 Mapping Child。原始框架不能被已合并的候选节点代替；框架标题只作结构输入，不开放其正文为事实 Evidence。结构和正文路径必须属于当前上传文件的 Corpus；没有结构文件的 Markdown 按语法树提取标题，支持 Setext 且忽略代码块内的井号。旧标目录用于判断层次和内容归属，旧项目地域、规模、年份及能力声明仍须按来源证明范围处理。Child 对照目录后通过既有目录操作落实独立写作主题；锁定时必须提交非空结构对照结论，解释采用、拆分和不适用的内容。已有叶节足够具体时可以保留，Host 不要求为增加数量而拆章。

S5 Writer 与 Reviewer 都接收确认目录及当前祖先路径，按父子关系、同级节点分工和本节任务检查主题归属。目录是否拆分及材料应放在哪里均来自项目输入，不按固定行业词、章节名称或层数决定。叶节正文使用段落、列表、表格等表达，不建立未确认目录标题；提交、候选验证及恢复检查拒绝根标题以外的 Markdown 标题，并返回具体标题问题。根标题编号来自确认目录，预览和导出保留已存子标题原文而不生成新的节内编号。

该规则部分替代[同一 Writer 与编号](../architecture/2026-09-07-s5-continuable-writer.md)中的节内编号机制，并补充[增量映射工具](../simplification/2026-09-07-s4-incremental-mapping-tools.md)的目录锁定条件和[章节研究任务](../feature/2026-09-03-bid-section-research-blueprint.md)的结构依据。这些记录的会话修复、增量提交、证据来源和确认时机仍有独立价值，保留并互链。

## Alternatives considered

**要求每个分支必须增加节点或达到固定层数。** 简单章节本来就可能可独立写作，节点计数不能证明内容归属正确；结构对照结论保留不拆分的理由。

**只加强关键词检索和写作提示。** 标题语境仍可能未进入模型上下文，提示也不能阻止正文创建未经确认的目录。完整结构直接进入任务输入，标题检查落实在提交与恢复路径。

**固定行业目录模板或章名到内容的规则表。** 同一主题在不同采购文件中可以承担不同职责；固定位置会把一个项目的修正强加给另一个项目。模型以本次目录、任务及来源结构判断语义，Host 只约束资料身份、工具提交和确认目录的使用。

**把新增标题转成加粗或自动补进最终目录。** 前者掩盖结构设计缺失，后者绕过用户确认和逐叶证据映射；需要成节的主题由 S4 落成目录节点。

## Consequences

每个分支增加完整目录的上下文开销，但正文检索仍按需读取分块，不自动注入整份旧标正文。S4 检查点版本为 3，拒绝复用版本 1、2 中没有逐项复核记录的完成分支，需要重置 S4 后重新研究；正式 Evidence Map 与确认目录格式保持不变。Host 能证明结构已提供、锁定有说明、正文没有额外 Markdown 目录；主题适用性与对照结论是否充分仍由模型判断，非空说明及无密钥回放不能证明语义质量。修改源码不会重写已确认项目或既有正文，旧项目需要重新完成 S4 结构确认后再生成正文。

## Testing

定向单元与真实 Loader 会话回放覆盖完整目录输入、无说明锁定拒绝、非法正文标题在同一 Writer 修正、目录职责同时传入 Writer 和 Reviewer，以及既有正文预览和导出保留标题。候选重绑哈希仍不能通过额外标题校验，恢复只重写违规节；真实模型对目录归属与深化充分性的判断质量仍需项目重跑验收。
