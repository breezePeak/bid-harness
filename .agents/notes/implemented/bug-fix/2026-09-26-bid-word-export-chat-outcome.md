# Agent Note: Word 导出终态显示在聊天时间线

Status: implemented

## Problem

独立 Word 导出的成功或失败只在导出页和输入框上方的 S6 计划中可见。计划表示执行步骤，不能明确回答文件是否生成、文件保存在哪；切换页签或刷新后，用户需要回到导出页查找结果。

## Decision

浏览器把每条终态 `bid.docx_export.changed` 事件投影为该会话聊天时间线中的持久消息。成功显示“Word 导出完成”和 Host 在生成时记录的绝对 `filePath`；失败显示“Word 导出失败，未完成”和错误原因。每条终态事件使用自身序号定位，重试后的成功保留此前失败记录；运行中的里程碑不生成结果消息，也不进入模型上下文。

完成态继续保存项目内相对 `path` 供下载与项目恢复使用。旧 Session 日志没有 `filePath` 时，聊天显示相对路径并提供导出页入口；新导出由 Host 使用项目根目录和已校验的相对路径构造绝对位置。同项目的其他主会话保留各自聊天记录，导出结果消息属于发起导出的会话。

## Alternatives considered

**只在完成的 S6 计划中追加文件路径。** 已完成计划长期占据输入区，且阶段步骤与最终文件结果混在同一组件中。

**让模型生成导出结果回复。** Word 生成可在模型回合结束后完成；模型回复无法作为文件成功写入和校验的权威结果。

**把相对 `path` 改成绝对路径。** 下载和项目恢复仍需项目内路径，直接替换会改变既有操作语义；独立的 `filePath` 只负责显示生成时的位置。

## Consequences

用户在发起导出的会话里可直接看到终态和文件位置，刷新后仍由日志重建。项目搬迁后旧消息中的绝对位置表示生成时的保存位置；导出页按当前项目状态处理下载。一次导出仍由[独立 Word 导出任务](2026-09-23-bid-independent-word-export-task.md)记录里程碑和结算；源码 Loader 回放核对实际 DOCX 与绝对文件位置，浏览器回放核对终态消息。
