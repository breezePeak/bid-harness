# Agent Note: Bid 目录与响应点身份由程序绑定

Status: implemented

## Problem

目录与资料研究中的节点、业务条目和响应点身份已经存在于程序持有的对象中，但部分模型输出仍要求抄写 ID。提示中的格式示例可能与当前评分身份不同，精确复制要求也不能保证引用正确。即使响应点引用合法，资料研究仍可分别保存响应点与评分选择，遗漏已经由正式清单唯一确定的所属评分项，导致目录发布失败；恢复同一检查点不会改变这个缺失关系。

## Decision

S3 评分拆解、语义复核及招标更新后的补分析只接收评分对象的位置和响应文本；程序绑定当前评分 ID、连续顺序、版本和稳定响应点 ID。初始目录与整本重生成只接收节点父位置、业务位置与框架标题位置，程序分配章节 ID、计算树层级、同级顺序并恢复精确引用；模型通过数组排列或插入位置表达语义顺序。局部修复与质量复核使用同一对象位置规则，不接纳模型提交的身份字段。各模型入口均由无文件工具的独立 Child 返回结构化语义，程序应用操作并保存候选、修复凭据和重生成差集；损坏的持久 JSON 原样保留并拒绝读取。Main 的目录编辑与能力任务只提交对象位置及同级插入位置，程序绑定草稿身份、版本及正式顺序。持久目录、评分候选、编辑操作和原生 SDK 继续使用完整身份。

对象位置只在本次请求提供的输入顺序中解析。未知或越界位置拒绝接纳，不按标题、文本相似度或 ID 格式猜测对象；当前评分对象可以使用任何合法 ID 格式。已发布且与当前评分输入匹配的响应点清单直接复用，恢复不会重新分配已有响应点身份。

S4 在接纳写作职责、保存和恢复研究检查点、从 Evidence 建立基线以及发布最终目录时，统一从正式响应点清单派生所属评分项与文字快照。显式选择的评分项保留，响应点确定的所属评分项去重补齐；程序不扩大响应点或需求的业务选择。未知响应点仍拒绝处理，共享目录校验继续检查评分关联和快照一致性。

失败后的恢复检查从真实会话通知取回原 Work，并读取该 Work 实际执行目录的资料研究进度；专用候选不存在时返回不可读诊断，不借用正式目录或其他 Work 的进度。

本决定补充[稳定目录草稿与响应点](2026-09-01-bid-persistent-outline-response-points.md)中的持久身份分配，以及[章节覆盖索引绑定](2026-09-04-bid-chapter-coverage-host-binding.md)中的程序派生原则。

## Alternatives considered

**要求模型逐字复制当前合法 ID。** 当前对象清单可以消除错误格式示例，但复制仍是随机输出，也让恢复依赖模型补写程序已经知道的关系。因此模型只选择输入对象，身份由程序绑定。

**放宽校验并按文本匹配评分项。** 同文条目和语义相近条目不能据此确定身份；程序仅从正式对象位置和响应点清单绑定，保留未知引用拒绝规则。

**只修改最终目录或让模型反复修复评分关联。** 研究结果、操作记录和已完成检查点仍可能保留错误关联，后续恢复又会产生同一问题。确定性关系在每个接受路径统一派生，最终校验独立保留。

## Consequences

模型仍负责章节职责、评分语义和业务覆盖选择，程序负责身份及能从正式对象唯一推出的关系。位置协议要求每次模型调用冻结输入顺序，结构变化后必须使用最新对象表。持久产物格式不变，历史研究检查点恢复时可补齐确定性的评分关联；未知对象和真正的业务缺项仍阻断。

## Testing

单元测试覆盖模型 Schema 排除原始身份、位置越界拒绝、程序节点分配、评分顺序及框架引用绑定；S4 回归覆盖只选择响应点的提交，以及已完成检查点缺少所属评分关联后不启动研究 Child 的恢复发布。真实 Loader 无密钥回放覆盖评分拆解、目录生成、局部修复、质量复核及 Main 目录编辑和重规划；真实 API 验证四个 S3 模型阶段不提交任何身份或派生字段，程序落盘后完整校验通过。
