# Agent Note: 恢复身份、候选与单飞调度的生命周期关联

Status: implemented

## Problem

失败通知之后的清理诊断可能遮蔽原 Run；完成检查点与修订草稿被当作互斥成果时，合法修订会在 Writer 前拒绝。通知确认期间的新失败可能被单飞请求吞掉，用户停止后重新继续也可能沿用耗尽窗口。全局目录 Reviewer 的启动、结果和清理若没有共同的所有者，超时会遗弃迟到 handle，清理异常也会覆盖原执行错误。

## Decision

失败恢复从当前任务投影、Run 启动身份和对应失败终态通知确定生命周期区间。身份包含原 Run、epoch 和完整 Work 描述，清理通知只作诊断。新 Run、停止、阶段重置和其他权威转换阻断旧失败回扫，相同状态的重投影保留关联；记录不足时拒绝。已发布能力任务的用户纠正属于新接纳的任务转换，必须有完成凭据、之后的直接用户消息、当前纠正状态及新通知中的精确 Work，不能复用完成之前的失败通知。

正式正文及其 metadata、审核、来源、Hash 和语义修订关系与未发布 reviewed_candidate 分别校验。正式基线和合法草稿可以同时存在；修订入口仍要求全书正式基线有效，再将目标移出本轮完成集合。正式身份缺失时只依据正式审核 artifact 的身份和对应 accepted attempts 重建，身份冲突不猜测。草稿独立绑定计划、epoch、证据和依赖，进入当前修订要求的复核及整改；正式正文继续决定修改范围。单章和批次均持续保存执行日志，重试沿合法的 queued、running、reviewing、repairing 迁移。只有发布成功才替换正式 final 身份并删除接替的草稿。

实际选中的候选决定 Writer；原父会话由现有 resolver 使用规范项目路径、当前候选 Run signal 和共享 Promise 缓存惰性恢复。整章恢复不预先固定正式 Writer，段落直修仍核对正式 Writer 与选区。清理只释放本次恢复的父会话。

恢复驱动在执行任何可能重入的 Session 回调前登记单飞条目。并发触发共享同一个 Promise 并合并一次后续核验，每次重新读取当前目标、窗口、可用性与停止状态。最后检查和撤销条目之间没有 await；异常交给原退避与预算，timer 接管后不立即循环，卸载等待合并的完整操作。

用户停止保留的已分类失败沿用原失败的继续资格。Host 在项目锁内准备操作后核对 live Main、原会话和 Work、Run、revision、同一条真实用户消息及其失败和停止边界，再通过既有 bid.recovery.requested 追加一次有限 continuation。相同 Run、updatedAt 和 user_stop 的重复投影不是新停止；普通执行中止不增加窗口，自动恢复仍拒绝 user_stop，等待输入仍走原问题链。

S4 全局 Reviewer 的 start 和 result 共用当前 Run 的 childTimeoutMs deadline，实际等待响应融合 signal。执行结束先关闭 timer 和 listener，随后由同一 Run 观察启动事务及 handle dispose。启动拒绝由工厂回滚，迟到返回的 handle 由调用者释放。清理期限只报告资源阻断并继续等待静止；执行主错误保留 code、message 和 cause，清理错误另留诊断，没有主错误时清理失败向外暴露。

## Alternatives considered

**回扫最后一条 failed 或重新追加旧失败通知。** 无法区分新 Run、重置和迟到诊断，会把已结束任务重新授予执行身份。

**草稿替代正式基线、删除草稿或优先固定正式 Writer。** 前两者分别放松修订保护或丢失已审工作，后者恢复错误的原父会话；两份成果需要独立证明与实际选择。

**每个 request 增加恢复轮次或在 finally 中撤销 pending。** 前者放大预算，后者留下已返回但仍登记单飞的丢失窗口。运行时核验标记不构成新的持久任务状态。

**停止后新建 Work、清空历史或向所有 suspended 授予额度。** 会扩大原授权和执行预算。有限窗口由原 Session 接纳事实投影，已有用量保持不变。

**分别计时 start 和 result，或超时后遗弃启动 Promise。** 前者扩大实际执行期限，后者泄漏晚到资源；提前释放写锁也不能证明旧执行静止。

## Testing

五组新增回归分别替换为提交 044261ac83fa45771ec82e535cdc8aa2c5e11139 的对应实现时均失败：清理诊断使身份缺失、批次修订在 Writer 前拒绝、合并请求漏发通知、停止后沿用耗尽窗口、全局 Reviewer 缺少清理观察。恢复当前源码后，包含相关边界的 24 个定向用例通过；最终十二个受影响测试文件的 674 个用例全部通过。新增 Host 竞态通过真实停止和工具入口继续，首次执行再次 TIMEOUT 后历史用量为 4、窗口用量为 1/3、累计上限为 12，旧确认放行后自动通知 Main 并再次执行原 Work；持久化错误与合并请求的回归同时验证派发退避及预算上限。

三组应用回放的 24 个场景分批通过；修正时序的两个已保存计划场景又连续两次独立只读重放通过。Host 类型编译及库构建通过，变更 TypeScript 文件规范检查通过。真实 S4 语义 e2e 在本机缺少模型凭证时跳过，不计为通过。应用回放保留完整内容比较；S4 历史故障在真实终态提交前注入，分片按 Host 描述身份排列；S5 已保存计划在夹具中控制摘要发布、真实 Inbox 投递和领取事务起点，模型输出等待 running 事务退出；同一 revision 的投影与模型事件具有确定顺序，未删除或归一化来源序号。

## Consequences

恢复保留原任务、请求、候选和累计用量，付出的代价是在清理无法结束时继续占用项目写锁。历史记录缺少足够关联证据时保持拒绝，不按同阶段或错误文案推断身份。回归覆盖真实 Host 和工具入口、Writer/Reviewer 执行、延迟清理与 flush、停止后新窗口、Session 重放、正式正文保护及不匹配证据拒绝；应用回放按 Host 分片身份对应完整审核内容，不按 locale 或完成顺序编号。真实模型语义验收仍依赖部署凭证。
