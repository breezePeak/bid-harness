# Agent Note: S4 产物、重置与联网准入边界

Status: implemented

## Problem

S4 的计划、日志、检查点、证据映射和 Web 来源清单曾把 `schema_version` 当作可恢复条件，导致格式变化与阶段重置互相阻断；阶段重置也可能遗留 Work 请求和私有工作树。联网执行只检查工具注册，无法证明当前 Provider 和凭据链可用；终审修正还可能丢失草稿目录变更。

## Decision

S4 产物只依赖严格的内容结构、输入身份、来源身份和运行归属校验，不再生成或要求 S4 自有版本字段。旧 S4 运行数据不迁移；重置通过 Work Descriptor 的 stage 归属清理对应请求、请求附属目录和 `runs/<workId>/`，无法确定归属的孤儿路径报告并停止。

Web Runtime 提供不携带密钥的 Provider 诊断，S4 在调度 Child 前按执行时相同的 Provider 选择规则检查 search/fetch，Child 挂载后再次核对工具和 Provider。Tavily 错误保留 HTTP 状态与限流信息并区分认证、限流和额度失败。

Final Check 的批量修正使用独立草稿状态，只有完整草稿提交成功后才回写目录、映射和复核状态；前置任务或候选身份失效时不直接恢复旧终审。

## Alternatives considered

**保留版本号并增加迁移分支：** 未采用。S4 旧数据已经由重置失效，迁移会扩大恢复路径并让旧结果继续冒充当前阶段输入。

**只在工具注册表中检查联网：** 未采用。工具注册与 Provider 可用性是两个不同边界，凭据解析失败必须在研究任务创建前暴露。

**修正后直接复用原状态：** 未采用。修正可能改变目录和复核指纹，必须以独立草稿原子提交并重新产生待审项。

## Consequences

S4 格式变更需要重置后重新生成，不能从旧检查点续跑；重置会清理对应阶段及下游 Work，但保留原始上传文件和有效上游输入。Provider 诊断只能证明本地配置与凭据可解析，不能代替首次真实请求对远端认证和网络的验证。
