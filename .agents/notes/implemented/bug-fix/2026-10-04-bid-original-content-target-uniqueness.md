# Agent Note: Bid 迁移原文单一目标与发布次数核验

Status: implemented

## Problem

原文迁移要求跨源章副本具有相同归属，但模型仍可用 share 把所有副本分给多个目标。每个目标各保留一次原文仍会在交付正文中产生重复；最终核验仅判断原块和原图是否出现，无法拒绝重复完整载体。

## Decision

原文保留任务的正式原块只能 move 到一个目标。相同原文的副本完整登记并具有同一个目标，Host 按正式源文件份数保留，合并候选新增副本；独有新增内容保持完整。模型结构化提交和原生迁移使用同一拒绝路径，不能把已拒绝的不同归属改成 share 通过校验。其他章节需要交接关系时单独编写说明，不复制原文载体。

迁移索引依据正式原块的完整文字恢复候选中粘连的块边界，同源重复和跨源重复使用同一分配约束。输出保留每个源片段的字节，并在片段之间补齐 Markdown 空行，避免段落、表格或图锚点与下一标题粘连。表格引导、表题和表格一起迁移。

迁移目标同时提供当前完整目录的 outline_position 和分配子会话的局部 position。步骤中的目录位置按前者对应到章节标题，结构化 target_positions 只使用后者；不同模型上下文之间不把裸位置数字当作同一身份。

发布核验分别统计当前可写叶节中的原文字节块和归一化原图，与任务原始范围的正式源文件出现次数比较。原有重复不因核验被改写；新增副本、减少次数或缺失均使任务目标未达成，不能写入正式发布凭据。旧父节点保留的历史正文不计入交付正文。

计划和产物核验通过隔离子会话的 structured_output 提交。Host 在工具接纳前核对证据完整读取及完整范围引用，未读或漏读时返回证据位置和补读起点，子会话补读后重新提交；最终绑定仍执行相同核对。核验器不能靠结束文本绕过，也不因可修正的未读引用直接中断整个 Work。

已开始写作而原文迁移需要纠正时，新的直接用户消息可授权 restart_pending。Host 保留已接纳前缀和旧候选历史，从前缀结果重新迁移完整原写作范围，再写作审核；不导入尚未提交的写作候选。自动恢复和 replace_pending 仍复用候选，不替用户选择重新执行。已有步骤提交凭据、目录改动、原文删除和缩小迁移范围均不能通过此入口。

本决策收紧[目录与正文迁移](../architecture/2026-09-24-bid-outline-content-reuse.md)的正式原文共享，并补齐[恢复流程](2026-09-28-bid-host-recovery-continuation.md)中的跨源副本约束。两项记录仍约束结构、授权、检查点和候选生命周期，保持活跃。

## Alternatives considered

**仅要求跨源副本具有相同目标组。** 多个目标组成的 share 同样满足该关系，但仍重复完整原文、表格和原图。

**让 Reviewer 删除多余副本。** 原文只读保护阻止 Writer 删改载体，章节审核也不能证明其他章节没有同一副本；错误应在迁移提交时反馈，并由全任务发布核验再次检查。

**只检查候选是否包含原文。** 完整出现无法证明未复制，也不能区分源文件原有重复与迁移新增重复。

**所有恢复都复用写作候选。** 有效候选应在网络故障后续用，但错误原文迁移需要先纠正；不区分两者会把错误归属持续带入下一轮写作。

## Consequences

正式原文保留任务不支持跨章 share；候选新增内容的显式共享仍由迁移分配处理。语义归属仍由模型按用户要求决定，Host 的字节和次数检查不代替语义判断。

定向测试覆盖原生迁移拒绝共享、同源和跨源副本合并、粘连正文索引、表格与标题分隔、原有重复份数和独有内容保留，以及语义核验误判时对重复正文和重复原图的拒绝。六子章 Loader 回放在同一分配子会话依次拒绝漏块、表题分离和共享原文，再完成全部写作、独立审核与正式发布。

迁移纠正 Loader 回放保留同一 Work 和已完成目录步骤，用新用户消息重新迁移及写作发布；定向拒绝测试覆盖原授权冒充新授权和遗漏原写作章节。

核验回放只读正文首字符就提交完成判断，同一子会话收到未读区间拒绝后补读，正式凭据在完整核验前仍不存在，不重跑 Main 或已完成业务步骤。
