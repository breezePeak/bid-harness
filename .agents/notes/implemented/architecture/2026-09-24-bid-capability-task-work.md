# Agent Note: Bid 同一 Work 的能力步骤与结果发布

Status: implemented

## Problem

跨阶段修改需要多个能力协作。按阶段分别启动 Run 会让前一步的目标身份、已完成文件和用户授权散落在不同恢复记录中；直接发布整个章节目录又可能覆盖任务范围外的正式成果。

## Decision

`capability_task` 是单一 Work kind。不可变请求冻结真实用户消息原话、选定审批意见、接纳时的待处理队列、完整用户计划、根范围、正式输入摘要和任务前状态；模型从已记录的 inspect 对象表选择位置，Host 绑定章节、业务条目、意见、模板、消息及历史 Work 身份，并生成 Work 与步骤 ID。原生目录编辑沿用该次 inspect 的草稿 CAS；模型不提供身份、摘要或偏移。目录迁移时序由程序从后续重组能力或明确暂缓正文的目标推导，模型不提交迁移开关；校验错误使用模型位置字段名，缺少来源仍拒绝接纳。后续计划用替换未完成步骤或追加步骤表达，Host 定位原 Work 和起点。`BidRunCoordinator` 为整个序列只接纳一个有效根 Run，步骤共用该 Run 的取消、Child 收敛与提交权限。`runs/<workId>/task-checkpoint.json` 记录完成结果、运行中步骤、等待输入和计划补丁；补丁不改请求 SHA，后续消息授权及失败时原授权复用见[能力重规划](../bug-fix/2026-09-29-bid-capability-replanning.md)。

每一步使用独立候选目录。Host 按当前确认目录、任务根范围及前一步的真实 `target_section_ids` 解析作用域；适配器只能声明预先允许的精确文件。业务 Validator 核对结果后，步骤文件和步骤回执同批合并到 Work 候选。没有步骤回执时，重试从 Work 候选重新生成该步骤目录，避免把未发布的文件当作新基线。最终发布前由隔离只读子会话按冻结来源核验实际产物，Host 另行核对真实目录节点、文件摘要、Writer 身份与完整审核或连续 Delta 审核链。既有章节的基线与候选摘要对照进入核验输入，范围外对象变化由 Host 拒绝。核验模型只返回语义要求及按输入顺序排列的判断，Host 绑定来源、章节、要求索引和实际文件摘要；章节记录摘要不充当文件摘要，虚拟路径与不匹配摘要仍拒绝。S4 私有工具选择目录、业务、研究依据、材料与复核对象位置，目录复核覆盖记录由程序生成；S5 私有规划与审核同样选择章节、验收和合规对象位置。Host 执行父会话仅接纳明确的阶段指令，Child 报告与结算通知不能触发额外模型回合或文件工具写入。保留原文的 Writer 只用位置占位符安排原文块，由程序插入精确内容并继承原图定义。恢复原 Writer 时验证会话 Header 的原 parent 和实际项目，共享 parent 的恢复句柄且只释放本次拥有的句柄。业务归属、迁移块和段落替换按输入顺序绑定；需要选择具体意见或修复块时，模型只提交位置，程序写入持久身份。原始来源要求完整保留迁移原文时，逐项判据记录该要求，Host 对照原段落、表题、表格和归一化流程图定义，拒绝语义 satisfied 漏掉的删改；原章标题由新目录标题替代。局部步骤恢复保留已绑定当前输入的写作候选；目录变化使旧回答依据待复核，不凭管理备注制造业务资料缺口。任务 `goal` 或 Reviewer 的 satisfied 不能替代来源。同一 Work 的计划拒绝、补丁及完成步骤由 Host 提供给后续核验；原文、表格和流程图保留情况由程序对当前可写叶节核对，重复写作已完成叶节仍提供原文保留块。核验失败保留候选和已完成前缀，原 Work 可替换后缀或追加步骤；真实授权问题须澄清。最终发布只替换已核对文件，并在同一 PublicationBatch 写入发布凭据、逐项核验及已满足意见；结算合并最新队列且拒绝来源被修改的意见。正文批次能力在当前候选复用段落修订、各章原 Writer parent 与统一调度，不嵌套项目操作。

重启首先前滚已有发布事务，再校验正式凭据及文件。正式提交已完成时，Host 只补任务前状态、Run 完成事件和公开主会话的有界结果通知；没有提交凭据时从检查点与候选回执恢复，完成步骤不能只凭内存标记跳过。原生修订只在已记录真实请求的入口调用与所属 Session 内授权，局部修订的整书审查另由独立能力执行。公开能力工具持久接纳后返回已启动，后台执行允许同一 Main 接纳运行期新消息，结果从完成通知与凭据核对；内容与导出组合的完成通知等待导出结算。纯章节审查的修复建议或外部资料缺口保留在报告中，不阻塞报告交付与排队接续；纯整书审查核对实际正文与当前目录摘要，正文交付仍执行完整质量和输入版本校验。首次写作计划由持久已回答请求绑定当前 Main 身份，有效计划优先于初始请求记录。能力执行本身需要补充业务输入时，Run 以 `awaiting_input` 挂起，原生问题及真实自由文本答案进入 Session 日志；Goal 自动恢复不处理这一原因。

正文批次处理完整任务相关意见的子集，语义核验仍覆盖全部相关来源。内部失败以原错误码和单元身份进入 Run 恢复，成功候选与稳定批次保留；真实缺输入及其依赖等待用户，冲突和凭证问题阻断自动恢复。目录授权在原基线核对，合法退役来源按结构操作、当前目录摘要和 reassignment 解析到结果目标，原身份保留用于来源、原文核验及意见结算。范围外节点的属性、正文及彼此的兄弟顺序必须保持。审批对象表保留历史状态和原引用，新消息授权可绑定最新正文进行定向纠正；历史记录的读取不改变队列。

唯一末尾 `docx.export` 属于检查点的有效计划，计划补丁直接作用于该尾步骤。内容发布凭据保持目标未满足，独立导出成功后同批保存导出回执和最终意见结算，再发完成通知。导出失败重试读取已发布内容，不再执行内容步骤；缺失导出步骤的要求在计划核验时拒绝。

候选查询的对象表与业务数据共享已核对的 Work 工作区，避免把正式项目的章节位置及写作计划版本用于候选补丁。状态与恢复查询沿用最近对象表，不把候选选择静默换成正式项目位置；正文引用读取使用其正式来源。候选缺失撤回对象表，后续绑定须重新读取。冻结要求存在时，计划与产物核验均返回等长有序检查项，输出 schema 固定数量；Host 继续拒绝缺项，不把模型漏项解释为验收成功。`project-session.spec.ts` 覆盖候选版本绑定和缺失候选后的拒绝路径，源码 Loader 的任务恢复回放检查核验 schema 的来源及检查项数量。

目录写作注记可通过现有 `update_section` 单独修正；业务归属通过已有对象位置协议开放给 Main，章节与业务身份仍由 Host 绑定，归属可独立更新，不需要占位目录操作；新增或拆分时，执行器校验原范围覆盖完整承接到叶节后清空结构父节点，遗漏在候选落盘前拒绝；结构节点的显式业务归属仅允许全空，以清理叶节转父节点后保留的旧覆盖，不允许结构节点接纳新的叶节义务。语义产物核验检查待发布候选，正式发布凭据在核验通过后的原子提交中产生；要求核验输入已有凭据会形成无法完成的循环。目录测试固定注记更新及结构节点非空归属的拒绝路径，源码 Loader 回放检查发布前核验的模型契约和实际发布结果。

## Alternatives considered

**每个能力步骤分别启动 Run。** 步骤之间的取消和项目 revision 会形成多个恢复边界，前一步的结果可能在后一步失败时已成为正式成果，无法作为一个任务协调发布。

**发布整个候选目录。** 工作树复制了任务开始时的完整基线，目录替换会覆盖无关章节及其他已有文件；精确文件清单与同批凭据将发布限制在实际变更范围。

**修改原 Work 请求以保存计划调整。** 请求 SHA 是恢复身份；修改它会使旧 Run 的授权和输入摘要失效。后续消息授权保存在检查点的补丁记录中。

## Consequences

一条用户任务在失败、停止和 Host 重启后仍由原 Work 身份恢复，已完成步骤和正式结果可按 Work ID 独立读取，排队任务结果在释放项目锁后通过持久通知唤醒空闲 Main。独立导出保留稳定任务身份；内容凭据与导出回执都有效时才标记完整目标满足，历史记录缺少核验时保持未验证。代价是每个适配器都须列出精确写入文件并提供业务校验；候选步骤失败留下的文件不能绕过结果回执进入正式项目。`BidTaskState` 仍是唯一项目状态，步骤记录不成为第二套总控状态机。

本决定扩展[Run 生命周期](2026-09-13-bid-workflow-run-lifecycle.md)的 Work 分发，并沿用[公共能力契约](2026-09-24-bid-capability-contract.md)的业务输入与范围校验。两份记录的 Run 权限、默认路线和只读项目查询规则继续有效。
