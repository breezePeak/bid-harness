# Agent Note: Bid 上游理解的后期修改

Status: implemented

## Problem

招标规范化结论和评分选择可以在目录、正文或导出完成后被用户更正。直接重跑 S2 会覆盖已经确认的来源身份、评分响应点编号和后续成果，且无法区分事实更正与正文重写授权。

## Decision

`tender.update` 只接收已有招标 ID 的规范化字段编辑与独立评分选择。原文、来源引用和评分原始清单由现有编辑函数保留；选中的下游评分由原始清单投影。评分语义变化仅把对应项交给独立 Child 分析，Host 递增分配新 RP 编号，未变项沿用旧编号与文本；取消选择仅从下游清单移除该项。

Host 根据目录的 requirement、scoring、compliance 关联计算受影响叶节，将结果写入 `analysis/tender-update-impact.json`。已有正文保持原值；受影响的目录、资料、写作计划和执行成果需由后续能力复核。`writing.plan` 从当前用户 Session 提取真实消息，局部引用只进入对应章节，全书约束需项目范围授权，未改章节的 AC 身份保持稳定。两项能力均在步骤候选中写入并交给 Work 精确发布。

## Alternatives considered

**重跑完整 S2/S3。** 这会改变未受影响的评分项身份，并把后期理解更正扩展为全书重建。

**按标点切分响应点。** 评分语义不等于标点边界；现有 S3 已把该判断交给独立语义分析。

**同步覆盖正文。** 用户仅更正理解时尚未授权正文重写，故以持久影响记录交给后续能力闭合。

## Consequences

后期理解更正可与既有正文共存，但受影响章节不能直接视为通过最新验收。已取消的评分项仍可在原始评分清单中审查；重新选入时会获得新的 RP 编号。
