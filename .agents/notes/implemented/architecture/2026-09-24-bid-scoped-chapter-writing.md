# Agent Note: Bid 局部章节写作与审核

Status: implemented

## Problem

S5 原执行器按完整目录运行 Writer、Reviewer 和整书验收。目录调整后新增叶节需要继承已经分配的正文草稿与资料；若为局部任务直接重跑全阶段，会启动无关章节并要求尚未写出的章节通过全书交付检查。

## Decision

局部写作、只审核与原有完整写作、单章修订和批量修订使用互斥输入，复用同一个章节调度器。局部写作只把授权叶节加入待执行集合；已有完成正文按原修订路径复用 Writer，新叶节以草稿为输入启动新 Writer。只审核保留正文和 Writer 身份，失效审核由 Reviewer 重新生成；审核请求身份包含指令、正文、元数据与 Writing Plan 版本，相同输入的有效审核可复用。

执行计划、日志和 Writing Plan 仍与完整确认目录的哈希及叶节集合一致；新增叶节从模型给出的目录目的与写作说明形成新任务，Host 分配新的语义 AC 身份，未变章节的 AC 保持原身份，退役任务保存在目录重分配记录。局部 Manifest 只记录真实完成章节。强依赖读取有效完成记录；交接变化时范围外下游只返回待复核影响。局部步骤不启动全书合规和完成修复，完整交付仍依赖原有整阶段校验。能力适配器从固定章节位置及 Web 来源账本计算精确文件许可，并核对目标正文、元数据、审核和完整索引。

## Alternatives considered

**为局部写作另建一套 Writer 和 Reviewer 执行器。** 两套协议会分叉正文修复、视觉复核及证据引用规则，也难以共享原章节检查点。

**用批量修订模拟新增章节。** 批量修订要求原 Writer、完整已完成目录及修订前正文，新叶节不具备这些身份。

**让局部任务运行全书验收。** 合法的待写叶节会被误判成失败，并触发未授权的全书修复。

## Consequences

局部能力可以保留范围外已完成正文，同时维持正式计划和日志的全目录结构。审核重点改变时会产生新的 Reviewer 成本；未完成章节仍须后续写作，局部任务成功不表示整份 Word 已可交付。
