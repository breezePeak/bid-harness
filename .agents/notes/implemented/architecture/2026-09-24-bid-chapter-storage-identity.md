# Agent Note: Bid 章节身份与存储位置分离

Status: implemented

## Problem

确认目录的顺序会随着移动、拆分和插章变化。用当前位置推算 `chapters/sections`、`meta` 和 `reviews` 的四位文件名，会把旧正文、审核和 Writer 身份指向别的章节；部分完成项目还可能把未写章节误认为已有正文。

## Decision

`section_id` 是章节业务身份，四位 `storage_serial` 是由 Host 分配的磁盘位置。`chapters/execution-log.json` 在章节记录中保存序号，根级 `next_storage_serial` 记录下一个未使用号。`chapter-storage.ts` 统一提供三个产物路径；纯读取只使用日志、metadata 和 Manifest 中能证明的身份，正式章节写入在提交权限内补齐旧日志并分配新序号。迁移核对同一 ID 和同一序号的归属冲突；旧正文没有身份依据时拒绝猜测。未写章节的只读位置可以为空。

目录树仍决定标题编号和 Word 顺序。正文、审核、修订、工作台和页数估算通过固定位置定位章节。旧叶节转成父节点后，旧文件仍占用其序号；新叶节取得新号。四位序号耗尽时明确失败。

## Alternatives considered

**按当前目录重命名所有文件。** 重排会改写相邻章节的文件和 Hash，也使执行中或中断恢复的引用失效。

**用当前目录顺序推断旧文件身份。** 部分完成和插章时缺少一一对应关系，猜测会把正文静默归给错误章节。

**把文件直接改名为 section ID。** 这会扩大既有产物、Manifest 和历史引用的迁移范围；固定序号加身份映射可以保持现有四位路径格式。

## Consequences

位置分配必须在拥有项目提交权限的写操作中完成，普通浏览和导出不改变日志。缺少身份依据的遗留正文需要修复 metadata 或 Manifest 后才能读取；损坏的可选索引在 metadata 足以证明全部正文归属时不妨碍只读导出。测试固定目录移动后的正文归属、导出顺序、部分完成、冲突、重复迁移和序号容量。
