# Agent Note: Bid 局部资料研究

Status: implemented

## Problem

S4 首次研究和浏览器 remap 已有相同的来源工具与复核流程，但能力 Work 需要在已改目录和正文草稿上局部补充资料。沿用初次确认目录会研究旧章节；把 remap 的临时计划、整目录 Web 文件或未核对的模型结果发布，会使范围与正式确认目录失配。

## Decision

`evidence.research` 在独立步骤候选中调用现有 S4 remap，并按当前目录展开授权叶节。补充模式保留并去重旧材料，替换模式仅改目标映射。退役章节的资料映射随 `outline/reassignment.json` 作为研究候选提供，当前正文草稿只提供检索上下文；模型须重新判断适用性，不能把正文或旧映射直接当作新章 Evidence。remap 没有结构工具；允许深化的任务必须先经过独立目录步骤。

Host 在 remap 后检查范围外映射和既有 Web 来源未改变，复用 S4 的来源快照、分块、覆盖与质量校验。若研究修改写作说明，目录确认、Draft 与章节执行索引沿用目录能力的协调路径更新。Web 文件许可由严格来源账本导出精确快照和分块索引路径，能力只报告内容实际改变的文件。映射计划、日志和检查点只保留在 T05 的独立步骤候选中。

S4 初次研究中的目录拆分也会产生尚未分配业务归属的新叶。动态新叶任务从被退役的旧叶取得真实业务 ID 作为可选择的授权集合，模型逐叶提交 `coverage_override`；父任务与同批子任务允许这个临时未覆盖状态，全部研究合并后的共享覆盖校验仍会拒绝漏项。原先测试把父叶的全部 ID 默认赋给每个子叶，因此改为显式提交一个子叶的归属并核对另一个子叶为空。

## Alternatives considered

**为局部研究重新实现来源工具。** 现有 S4 已绑定本地文件分块与成功 Web fetch 的持久快照；新实现会产生两套引用和质量规则。

**把旧父章映射平均复制给新子章。** 同一材料对不同章节的用途需要分别判断，复制会把未研究的空缺伪装成完成。

**授权整棵 Web 来源目录。** 能力结果应只发布账本引用且真实改变的文件；目录授权无法证明变更范围。

## Consequences

首次全量路线保持原有 S4 行为；已确认项目可在同一 Work 中接续目录调整与局部资料补充。资料缺口保留为 `missing_topics`，企业事实仍须来自真实本地材料。局部研究的模型错误和基础设施失败沿用 S4 的失败语义，步骤候选失败不覆盖正式映射。
