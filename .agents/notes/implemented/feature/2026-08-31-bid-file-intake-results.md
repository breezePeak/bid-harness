# Agent Note: Bid 文件接入逐文件结果

Status: implemented

## Problem

文件接入按批次返回单一成败状态时，一个损坏的参考资料会掩盖同批次已经成功解析的招标文件，界面也无法说明具体失败文件和原因。文件大小仅由客户端预检还会让其他调用方绕过限制。

## Decision

Bid Host 逐个解析文件，并在响应中返回每个文件的角色、解析状态、错误原因和已识别格式。只要至少一份招标文件成功，Host 就保留成功结果；失败的参考资料或额外招标文件不会使整批结果失效。

Host 统一执行默认单文件 200 MB、单批次 500 MB 的大小限制。Web UI 在编码前执行相同的快速检查，并逐项展示编码、上传、完成或失败状态；Host 仍是最终校验方。

## Alternatives considered

**任一文件失败就拒绝整批。** 该方式无法保留已经完成的解析结果，也不能支持用户针对具体失败文件重试。

**把每个文件拆成独立请求。** 这会改变当前批次接口和调用顺序；逐文件结果已经能提供所需反馈，因此不引入新的传输协议。

## Consequences

调用方可以保留成功文件并只处理失败项，Web UI 也能提供逐文件进度和错误。Host 响应增加逐文件结果字段，所有接入方需要按该字段展示部分成功；批次仍要求至少一份招标文件成功。
