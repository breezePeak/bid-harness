# Agent Note: Bid 目录确认产物

Status: implemented

## Problem

S3 初步目录和 S4 深化目录需要分别保留用户确认结果，后续写作必须读取经过结构与覆盖校验的最终目录。章节拖拽改变位置，关联资料需要保持章节身份。

## Decision

S3 和 S4 在 `waiting_user` 接受 Host 定义的目录操作，以 Revision 和 SHA-256 比较并保存草稿。S3 确认保存 `outline/initial-confirmed-outline.json`；S4 确认保存 `outline/confirmed-outline.json` 与 `outline/confirmation.json`。S5 只读取最终确认目录作为章节结构来源。

浏览器只允许正式 `outline.sections` 章节发起拖拽，复用 `move_section`，由 Host 重排同级顺序并重算整棵子树的层级。落点预检拒绝自身、子孙、可写父章节、空结构章节和同级重名；Host 仍负责最终结构及覆盖校验。现有目录规则没有最大深度配置。移动不更换章节 ID，不修改 Blueprint 字段或重建 Evidence；S4 正式确认保留对语义受影响章节的原有复核。

只读审核接口单独返回 S3 确认基线、S2 要求及评分记录和 S4 Evidence，不把资料塞入持久化草稿。S4 Diff 按稳定 ID 分别比较标题、编写字段、关联集合、父节点和两版都留在同一父节点下的章节顺序；原始 order、level 和展示编号的顺延不构成主动移动。对象属性顺序和集合型关联排列不构成内容修改。差异过滤保留祖先和联动上下文，只有子项变化的父节点单独标记；删除章节保留在基线栏且可查看原内容。详情通过章节 ID 关联资料，展示顺序不决定业务身份。

两侧共用选中 ID，只读基线允许点击和折叠；无对应 ID 时不回退到第一章，也不按标题猜测对应关系。目录视图使用现有 Composer overlay 布局，约束审核宿主高度并预留聊天区；选中时只调整对侧树的滚动容器，不滚动整个页面，目标已在可视区域时保持位置。选中描边在悬停和焦点进入行内控件时仍显示，差异标签独立保留颜色。

## Alternatives considered

**只记录确认布尔值。** 用户修改无法成为后续写作的持久化输入。

**使用可编辑草稿充当 S3 基线。** S4 编辑会同时改变比较依据，无法辨认深化结果。

**按显示编号关联资料或重跑映射。** 编号随移动变化；稳定章节 ID 已能保留已有资料。

**整节点序列化比较和原始 order 比较。** 属性排列及新增章节引起的编号顺延会制造大量差异，无法区分目录结构与章节信息更新。

**对目录行调用 scrollIntoView。** 未约束的祖先滚动容器会跟着移动，固定表头和 Composer 可能遮住目标；目录联动只需要调整对侧树内的位置。

**仅在浏览器验证修改。** 覆盖与图结构校验必须由 Host 强制执行；浏览器预检只负责禁用无效落点。

目录标题默认只读，行尾编辑图标开启修改，失焦时提交保存。拖拽保留原目录显示，间隙插入线由拖拽事件控制；章节下方缩进落点插入为首个子章节，使落点与保存位置一致。

## Consequences

S3/S4 共享章节编辑和保存链路，S5 继续消费唯一的最终确认目录。目录只读上下文不触发生成或资料映射。组件测试覆盖合法与非法拖拽、字段差异、稳定 ID 双向联动、过滤上下文及删除章节只读；真实 Host/Chromium 测试验证折叠祖先展开、悬停描边、局部滚动和可视范围，以无密钥界面快照固定结构变化详情。Host 测试覆盖保存后读取与基线、Evidence 保持；源码 Loader 快照固定真实装配返回的基线与关联资料。
