# Agent Note: S4 确认后直接启动 S5

Status: implemented

## Problem

用户确认 S4 最终目录已经表达开始正文编写的意图，再询问整体意见会增加一次必经操作，并使 S5 启动依赖浏览器的确认模式。

## Decision

默认路线只在 S2、S3、S4 产物校验后等待确认。S4 确认成功后，Host 在同一项目操作中生成或复用当前确认目录的 Writing Plan，随后执行 S5。首次默认计划不包含用户原话或虚构引用，并在 S5 Work 创建前持久化，保证输入指纹绑定实际计划。

浏览器两种确认模式都直接启动重置后的空 S5 入口，不发起意见问答。已保存的显式写作请求、停止和恢复状态继续按原有规则处理；运行中的用户补充要求仍更新版本化写作计划。

本记录部分替代[写作要求门禁](2026-09-09-bid-s5-writing-requirements-gate.md)、[自动确认模式](2026-09-11-bid-automatic-confirmation-mode.md)和[原生写作问答](2026-09-15-s5-native-writing-requirements-question.md)的默认启动决策；这些记录仍保留显式请求、真实引用和恢复规则。

## Alternatives considered

**只让前端选择自动模式。** 启动仍依赖浏览器挂载和远程调用，无法保证 Host 接到 S4 确认后连续执行。

**删除写作计划。** Writer、Reviewer 和后续用户补充要求仍需要章节任务与版本身份；默认计划可以直接由确认目录生成。

## Consequences

S4 确认后的正常路径没有 S5 等待确认事件或意见问答。Host 测试验证默认计划、章节启动和不生成提问记录；浏览器组件测试覆盖两种确认模式；真实 Loader 的 S5 回放固定无额外确认的会话事件。已有显式请求的恢复机制不属于此次删除范围。
