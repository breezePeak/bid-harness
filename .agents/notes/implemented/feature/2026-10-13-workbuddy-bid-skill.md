# Agent Note: WorkBuddy 独立标书编制技能

Status: implemented

## Problem

标书领域积累的评分响应、证据使用和审查方法需要由 WorkBuddy 直接执行，以使用其研究、文档和交互能力。现有 Host 工具依赖 DSH 会话、对象表与运行记录，复制提示词不能将这些工具和程序保证带到另一宿主。

## Decision

完整技能位于 [deliverables/bid-workbuddy](../../../../deliverables/bid-workbuddy/SKILL.md)，包含中文业务参考、独立 Python 来源与产物工具、Word 导出和可运行演示。WorkBuddy 执行语义研究和写作，Python 保存原件、生成身份、绑定引用、验证覆盖、迁移原文、替换选区和保存审查状态。它不读取或修改 DSH 正式项目状态，也不增加 Provider 或模型服务。

来源只追加；模型选择程序给出的位置和行范围，程序绑定身份与实际引句。这延续[身份绑定规则](../bug-fix/2026-10-05-bid-host-id-bindings.md)的原则，但独立技能没有 DSH 的工具结果来源证明：快照只能证明登记内容一致，真实抓取、提取正确性和语义支持仍由执行者核对。现有身份绑定记录继续适用于 DSH，本记录不替代其决定。

项目采用单协调写入者，请求与当前版本绑定。已有正文拆并须明确映射全部原文，局部替换由程序保留选区外内容；失效正文和旧审查不会继续满足内容就绪条件。正文就绪与签章、递交及视觉验收分开，人工事项不能用采购原文证明已执行。Word 导出从当前项目重新构建输入，防止旧就绪缓存绕过检查。

## Alternatives considered

**把整个 Host 包装成远程工具。** 这仍由原运行时承担研究与写作，需要搬运会话及工具协议，无法让 WorkBuddy 直接完成用户希望使用的研究过程。

**仅分发提示词。** 覆盖和原文保全将完全依赖模型自律，不能可靠拒绝过期请求、错挂来源和不完整迁移。独立程序保留这些机械检查，但不把程序通过包装成标书质量保证。

**移植完整编排框架。** 独立技能的串行接纳和文件检查点已经覆盖当前需要；多写入者并发、后台运行树与自动重试会增加部署和维护成本。并行任务只起草独立文件，交由协调者串行接纳。

## Consequences

核心编排和来源工具只使用 Python 标准库；Word 导出使用 python-docx 和 Pillow。依赖检查只报告环境，不隐式安装。复杂表单、OCR、网页搜索和最终页面渲染使用宿主的实际工具，因此必须披露相应能力缺口。内容 ready 不能替代真实业务评审和逐页检查。

真实 CLI 演示验证资料到全书输出；以实际 Python 执行 `scripts/test-bid-workbuddy.py`，完整验证非法来源、引用范围、过期请求、修改失效、原文迁移、局部替换和 DOCX 结构。独立检查使用与技能相同的 Python 环境，不需要包管理器启动。该技能不改变 DSH 模型提示、会话事件或运行时，无密钥 DSH 会话回放不覆盖此宿主；WorkBuddy 的真实工具选择与成稿质量需要在实际客户端验证。
