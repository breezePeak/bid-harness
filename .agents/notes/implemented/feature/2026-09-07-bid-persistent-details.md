# Agent Note: 累积详情入口与审核页面确认

Status: implemented

## Problem

按当前待确认阶段显示单一审核入口会使用户无法在后续写作时查阅已确认招标信息和目录。S4 的生成目录还会持续改写，直接展示工作文件可能把中间结果当成最终目录。确认与修改意见位于对话输入框上方时，用户需要离开审核内容才能操作。

## Decision

三个详情入口复用现有阶段产物。Host `getDetails` 在可读阶段返回招标信息和目录，S4 执行期间保留 S3 确认文件，S4 等待确认时展示已生成目录，确认后使用最终确认文件。页面刷新和新会话接管通过恢复的项目状态重新读取，不另存客户端确认标记或内容副本。

`BidDetailsView.outlinePresentation` 明确返回目录来源与发布状态、S3 确认基线、已有资料映射及读取错误。工作流阶段、目录展示模式和编辑权限分别判断：最终目录确认后继续展示 S3 基线、S4 最终目录与章节详情三列，`readOnly` 仅关闭修改入口。即使两版完全一致或资料为空也保留最终目录模式；基线与资料损坏显示对应文件错误。只读详情不进入等待待确认状态的 `getOutlineReviewContext`，不占用阶段操作，也不等待 S5 写作结束。

S3 待确认阶段使用临时“审核项”，确认后由常驻“目录详情”接替。S2–S4 的确认按钮、目录修改意见及错误都在审核页面，确认按钮与 S2 共用顶部右侧布局。S5 的“正文详情”从进入阶段开始显示，并在等待、失败和完成状态下保留已生成正文。

## Alternatives considered

**在浏览器缓存已确认内容和标签。** 缓存无法覆盖新会话接管，也容易在项目重置后展示失效版本；现有确认文件和项目状态已经提供持久依据。

**用当前处于 S4 或差异数量决定三列布局。** 工作流推进和零差异都不改变目录发布版本；伪造 S4 阶段还会混淆确认权限，因此布局使用 Host 返回的目录来源。

**S4 始终读取正在改写的目录。** 这会在任务尚未完成时暴露中间结构，必须以阶段发布点选择已有目录文件。

**S3 确认面板留在输入框上方。** 这使确认操作与审核内容分离；临时入口既保留 S3 确认前不显示目录详情的规则，也让操作集中在审核页面。

## Consequences

工作流执行、确认机制和产物格式保持原有职责。确认后的招标表格和目录导航只读，正文继续使用原有工作台和轮询。[按需 Word 导出](2026-09-04-bid-s5-persistent-review-export.md)及[通用 View 可用性](../bug-fix/2026-08-31-conversation-view-availability-and-portal-fallback.md)仍各自约束导出状态和会话组件归属。

## Testing

定向组件测试覆盖只读详情和正文持续展示；项目会话测试与真实源码 Loader 快照覆盖恢复后的产物读取。浏览器场景覆盖确认位置、标签累积、目录切换、正文轮询和刷新恢复。
