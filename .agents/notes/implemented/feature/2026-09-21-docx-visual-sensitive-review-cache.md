# Agent Note: S6 视觉敏感块审核缓存

Status: implemented

## Problem

S6 已能以所选原始模板合成 DOCX、嵌入原生流程图并刷新 Word 字段，但所有排版判断都止于结构校验和页数统计。流程图、表格和图片可能在真实页面中超界、裁切、重叠或严重挤压；正文、标题和列表通常不需要为此增加视觉模型调用。重复导出相同内容时重新审核每个视觉块还会增加成本和不确定性。

## Decision

S6 只把流程图、表格和图片识别为视觉敏感块。流程图使用 Host 分配的持久 ID；表格和图片使用所在标题摘要及块内顺序形成确定性 ID，不使用 Session ID 或随机值。普通文字沿用既有导出链路，不计算视觉审核任务，也不调用视觉模型。

每个块的 `inputHash` 使用 canonical JSON 后计算 SHA-256，覆盖块内容或原图片摘要、目标尺寸、所选原始模板摘要、页面尺寸与页边距、相关样式、块类型、Renderer 版本和 Review 版本。第一版使用整份原始模板摘要以保证模板变化不会误用旧结论；块内容仍独立计算，因此正文或其他视觉块变化不会使当前块失效。项目级 `word-export/visual-review-cache.json` 以 `blockId + inputHash` 保留历史 PASS、白名单调整、最终页面 `outputHash` 和审核版本。

产品 S6 入口在模板合成、Visio OLE 嵌入和 Word 字段刷新后复用现有 LibreOffice 转 PDF 能力，再按文字锚点定位目标页；无法定位时按视觉块顺序选择中心页。审核请求只携带目标页及相邻页、块类型、边界检查、已有调整和当前块允许的 JSON schema，并以 `bid.visual-review.request` 记录实际模型输入。相同 PASS 直接应用缓存调整并跳过 PDF 和模型步骤。

流程图和图片只允许等比例缩小，表格只允许缩小字体。每次调整只改变当前块的参数，但完整 DOCX 会通过同一正式 Renderer 重新生成并再次查看真实页面。一次块审核最多接受两轮调整；仍未通过时保存 failed 摘要并拒绝本次导出。此决策建立在[模板原位合成](2026-09-14-word-template-first-composition.md)、[模板库与真实分页](2026-09-12-bid-word-template-library-and-rendered-pages.md)和[结构化流程图](2026-09-15-flowchart-content-blocks.md)之上，不替代这些记录拥有的模板、分页或流程图来源规则。

## Verification

包级测试固定普通文字零调用、首次流程图 PASS、相同输入缓存命中、内容/页面/模板/Review 版本失效、表格与图片白名单调整后复核，以及多块文档只重审发生变化的流程图。既有 DOCX 合成、格式、导出、真实分页、PDF 页面和 Visio 套件继续覆盖共享链路。

## Alternatives considered

**审核每个正文块。** 未采用；普通文字的排版由既有 Renderer 和格式校验控制，为每段截图和调用模型会把局部风险扩大成所有导出的固定成本。

**审核 Markdown、OOXML 或块自身图片。** 未采用；这些表示无法显示模板分节、页边距、周围正文、Word 字段和 OLE 对象共同形成的最终页面结果。

**只按块内容缓存。** 未采用；模板、页面、样式、Renderer 或审核规则变化都可能让相同内容产生不同页面结果。

**让模型直接修改 OOXML或重新生成整份内容。** 未采用；模型只选择现有 Renderer 支持的缩放参数，正文和模板结构仍由确定性代码拥有。

## Consequences

未变化的视觉块只增加一次确定性 Hash 查询，普通文字不增加模型成本；同一项目可在重启后复用历史 PASS。模板摘要会使模板内无关修改也令视觉块重新审核，这是第一版为避免错误复用接受的保守失效范围。页面定位依赖 PDF 文字锚点；图片缺少可提取文字时使用块顺序近似并同时提供相邻页。LibreOffice 或图片模型不可用时，含未缓存视觉块的导出明确失败；纯文字导出和已有 PASS 缓存仍不依赖视觉模型。
