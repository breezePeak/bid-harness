# Agent Note: Bid 主会话能力工具与计划补丁

Status: implemented

## Problem

主会话能接纳新的能力序列，但旧业务工具仍只在少数阶段出现，后续消息也没有修改已保存任务剩余步骤的公开入口。模型在目录完成后继续修改时容易把兼容阶段当成业务权限。

## Decision

`bid_run_task` 始终提供任务根范围和有序步骤；`bid_plan_task` 只针对当前挂起的能力 Work 替换未开始的步骤后缀。补丁绑定后续真实用户消息，保留不可变初始请求、已完成步骤及原任务范围。保存补丁不自行恢复 Run。

旧目录、资料、写作计划和章节修订工具继续接受原参数。原生目录确认和 S5 热插入仍使用原入口；其他阶段通过能力任务执行。旧目录工具在能力路径核对当前确认目录的 CAS 身份，过期参数返回当前基线，不静默套到新目录。

## Alternatives considered

**让旧工具在所有阶段直接调用旧阶段操作。** 旧操作的确认状态、运行所有权和候选路径绑定内部阶段，扩大公开权限会绕过能力 Work 的范围与发布凭据。

**允许模型改写整个任务请求。** 已完成结果会失去原授权和恢复身份，重试也无法区分用户新增步骤与初始计划。

## Consequences

主会话可沿用旧参数，也可选择单能力或有序任务。计划补丁只改变尚未开始的步骤；运行中和等待输入的步骤先按当前生命周期收敛。默认整本路线仍由原生 Orchestrator 负责首次确认与阶段推进。
