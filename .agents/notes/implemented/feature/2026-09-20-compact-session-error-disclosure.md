# Agent Note: 会话终局错误使用紧凑披露行

Status: implemented

## Problem

终局错误可能包含重复的错误码、修复记录与底层解析信息。聊天流直接展示完整诊断时会形成大段正文，掩盖相邻的模型回复和工具状态；只截断诊断又会让排障信息不可恢复。[有界模型请求恢复](../architecture/2026-06-21-bounded-llm-request-recovery.md)继续负责错误事实、脱敏与重试语义，本记录只负责聊天流中的呈现。

## Decision

`turn-error` 使用共享的 `DisclosureRow`：默认显示一行红色摘要，包含“本轮运行失败”、可用错误码和诊断首行，溢出部分省略；字号小于普通消息正文。鼠标悬浮时状态点切换为展开箭头；整行支持鼠标、Enter 与空格切换。展开后显示完整的脱敏诊断与错误码，组件状态不写入 Session。

AUTH 脱敏、历史重放、重试耗尽后终局错误与重试行并存等行为保持不变。真实 Web 组合分别固定非重试 AUTH 错误和重试耗尽错误的默认折叠状态，组件测试固定展开交互。

## Alternatives considered

**永久只显示摘要。** 诊断会从浏览器界面消失，用户无法在不读取原始日志的情况下排障。

**默认展开完整错误。** 这保留了信息，却无法解决长错误占据聊天流主体的问题。

**新增专用弹窗或详情面板。** 终局错误只需要一个局部展开状态，共享披露行已经提供鼠标、键盘和 ARIA 语义；独立容器会增加没有额外能力的状态与布局。

## Consequences

聊天流默认只占一行并突出错误摘要，完整诊断仍可就地访问。长单行诊断依赖视觉省略而不修改持久化文本，因此复制原始 Session、历史重放和其他消费者不受影响。展开状态在组件卸载后重置，刷新不会把纯呈现选择写入会话记录。
