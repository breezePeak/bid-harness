# Agent Note: S5 项目风格与 CPA 按需生图

Status: implemented

## Problem

章节中的工程效果图、设备布置和方案场景需要由生图模型生成。已有流程图保存的是节点与连线语义，普通图片导出也没有生成请求、项目风格和资产身份记录。并发章节独立选择风格会使整份标书画风不同，修订与恢复重新请求还会重复计费。

## Decision

Bid 包集中配置和调用 CPA Images API，使用已有 Settings 与 `pp` Credentials 引用。前端选择服务实际公布的一个生图模型；项目在 S5 写作前冻结模型、连接和语义风格，首张视觉确认图片成为共同参考。作图与聊天分别配置，已有项目不随全局模型设置变化而混用连接。接口不接受新密钥字段，不向模型或项目文件保存密钥值。

Writer 只提交图像语义、比例和图片位置。Host 生成请求摘要、资产身份、不可变 PNG 路径和正文引用，复验正式账本、文件摘要与尺寸。图片查看复用[原生多模态链路](../feature/2026-09-21-bid-global-multimodal-image-input.md)，位置绑定遵循[程序身份规则](../bug-fix/2026-10-05-bid-host-id-bindings.md)。生成图片与[结构化流程图](../feature/2026-09-15-flowchart-content-blocks.md)各自保留其正文表示，三个已有决定仍适用于各自对象。

真实图片通过私有工具回执进入原 Writer 会话；恢复的 pending 图片必须重新展示或已有可证明的真实展示记录，才能确认。实际提示、模型、接口、图幅和参考附件在计费请求前持久化，附件原字节作为参考输入，使会话日志能够重建模型输入。模型决定内容和风格是否符合要求，程序控制权限、身份、字节预算、取消和发布。S5 在接纳时遵守 Word 的全书图片资源预算，正式章节 metadata 与图片通过同一 Work 发布；前端仅按当前项目已发布正文引用的资产身份读取图片。

## Alternatives considered

**把生图输出加入聊天适配器。** 当前消费者需要独立的 Images 请求和图片资产结果，聊天注册表提供文本回合与工具协议；改变聊天输出会扩大此次功能的影响范围。

**每章只使用相同提示词。** 语义提示不足以固定实际画风，也没有确定的首图与连接所有者，因此使用项目风格和已确认参考图。

**让 Writer 提交图片路径或复制资产身份。** 模型不能证明文件、来源与当前权限；程序发放位置并绑定真实身份，修复和恢复保持同一资产。

**失败时自动重试生图。** 超时不能证明提供方没有执行或计费，程序只复用已持久化成功结果，不自动重发不确定请求。

## Consequences

CPA 需要提供生成与参考图编辑能力，Writer 需要原生图片输入。图片增加提供方费用与附件存储，生成场景只表达拟议方案，不证明企业事实。项目重置 S2～S5 保留风格和参考图，S1 重置清空；不支持由章节工具替换项目已确认风格。

单元回归覆盖模型工具非法位置、真实图片展示后的确认、资产篡改、并发预算、恢复复用和项目授权；真实 Loader 回放覆盖 S5 生图、审核与 Word 图片嵌入。CPA e2e 通过已有设置及凭据执行模型发现、生成和参考图编辑。视觉风格仍由模型及用户看图判断，程序校验不替代业务与事实审核。
