# Agent Note: Bid 能力计划与独立导出展示

Status: implemented

## Problem

固定阶段计划不能表达局部任务的实际能力顺序；阶段标签也可能在已有正文仍可读取时隐藏工作台。Word 导出若混入尚未提交的能力候选，会让用户误以为导出包含了该候选。

## Decision

Host 从能力 Work 的不可变请求及步骤检查点读取计划摘要，公开主会话页面用现有计划列表显示能力顺序、排队、等待输入和失败。正式章节位置决定正文详情是否可见。`docx.export` 只允许作为任务最后一步，等前面的能力 Work 正式结算后使用既有独立导出操作。导出事件保留稳定操作身份，结果提示包含所读取 Markdown 快照的摘要。

执行步骤的必填 `description` 由主 Agent 用一句单行短摘要说明任务对象、动作和预期结果，最多 20 字；详细执行要求留在 `call.input`。初始任务、排队请求、重规划和持久记录共用非空、长度与单行校验。检查点中的已完成前缀继续保留摘要和结果，未完成后缀随计划补丁替换。界面以摘要为主行、能力及真实状态和结果为详情，挂起和完成后仍可查看，后续默认阶段不覆盖最近能力计划。读取异常保留同会话已读状态并标明未同步；切换会话清除旧计划的可见性。

## Alternatives considered

按当前阶段推测能力步骤会在局部修改中显示错误的完成进度。把 Word 作为普通候选步骤会突破独立导出读取正式正文的边界。按章节序号恢复选中内容会在拆章后指向其他正文。

**独立保存工作项清单。** 清单与可执行步骤没有逐项关系，重规划后容易显示过期承诺；直接展示步骤说明只需维护执行计划这一份数据。

**由界面固定生成修复步骤。** 无法表达主 Agent 根据实际资料选择的能力和依赖；界面只展示真实步骤，不预设评分项数量或阶段顺序。

**仅在界面截断步骤说明。** 截断可能丢掉对象或结果，也不会减少模型生成的长篇内容；摘要由 Main Agent 在提交时编写，完整业务要求通过执行参数保存。

## Consequences

界面读取 Host 的实际步骤状态，导出结果可对应到正文快照。能力计划需要页面定期读取检查点；导出操作仍使用原有模板、验证和生命周期机制。

步骤摘要是持久请求和检查点的必填字段，超长或多行的存量说明拒绝读取，不从能力名称伪造详细说明。定向测试覆盖非空、20 字边界、详细执行参数保留、首次提交和重规划拒绝非法摘要，以及排队、终态保留、读取失败和会话切换；源码 Loader 回放验证同一次用户授权中非法摘要的拒绝与修正、能力替换、实际修改和最终计划结果。真实模型验收检查公开计划摘要长度及单行约束；摘要的具体措辞仍由模型负责。
