# Agent Note: S5 整体写作要求门禁

Status: implemented

## Problem

S4 最终目录确认后曾立即启动章节关系规划和 Writer，用户没有机会在既有 S5 中说明整书目标、重点章节、风格、表格或旧标复用方式；S5 重置后的显式开始也直接执行。聊天中的临时要求既不能稳定恢复，也无法为章节任务提供经过范围判断的执行计划。

## Decision

`chapter_writing` 使用 `before_execution` 用户门禁。S4 确认和 S5 重置启动只进入 `waiting_user`，Host 按 `outline/confirmed-outline.json` 哈希保存 `chapters/writing-request.json` 并唤醒 Main Agent 发出一次自然语言询问。项目恢复读取该标记，因而刷新或切换 Session 不会重复询问；未获得确认时不存在章节执行事件。

Main Agent 通过 `bid_stage_inspect` 读取确认目录、招标要求与资料映射，负责解释要求、识别关键歧义与冲突并分配篇幅。只有用户确认安排或明确授权直接开始后，Main Agent 才调用 `bid_confirm_writing_plan`。Host 从当前询问边界后的会话事件保留用户原话，并把已确认计划写入 `chapters/writing-plan.json`；跨 Session 确认时使用工具提交的原文。计划与确认目录哈希绑定，版本由 Host 单调递增。

程序只允许计划覆盖确认目录中的可写叶节，每个叶节恰好出现一次。没有整书页数要求时，整书目标和叶节预算均为空；约数、下限、上限和区间保留不同约束类型，使用的叶节预算边界之和必须等于整书对应边界。结构节点没有预算，因此父节点汇总不会与子节点重复计数。估算依据属于计划，排版前的目标不冒充实际页数。

章节关系规划接收完整确认计划。Writer 接收整体目标、适用全局规则、当前叶节的详略与预算以及明确点名本章的重点；Reviewer 接收相同的本章适用项，但不接收可作为单章判错条件的整书页数目标。文档级核验可以读取完整计划，负责跨章目标与预算汇总。

运行中或已完成的 S5 接受新的普通消息时，Host 先取消并排空当前操作，再回到同一写作计划门禁。Main Agent 说明变更安排并提交受影响的可写叶节；Host 保存计划基线版本，`chapters/applied-writing-plan.json` 记录执行日志已经采用的版本。恢复执行只使这些章节及其强依赖下游失效，未开始章节自然采用新计划，其余已完成章节继续复用。计划文件只在旧操作排空后更新，旧版本结果不能越过计划版本边界提交。

## Alternatives considered

**新增独立写作规划阶段。** 这会扩展控制面阶段、重做 S4—S5 交接并形成第二套写作链路；门禁属于 S5 的执行前输入，不需要新的阶段身份。

**把用户原话直接广播给全部章节。** 这会把整书页数、局部重点和目录变更责任错误复制给每章，也无法表达冲突处理和非平均篇幅分配；语义计划先确定作用范围，再由 Host 装配章节上下文。

**由程序关键词匹配“页”“重点”并生成计划。** 约、至少、不超过、排版口径和资料可行性需要语义判断，固定规则会产生虚假硬指标；程序仅校验结构、目录身份和确定性汇总。

**只依赖聊天记录恢复要求。** 新 Session 不复制旧聊天，而且聊天压缩或上下文替换不能成为项目状态权威；项目 Artifact 保存询问身份、原话、确认和计划。

## Consequences

用户在 S4 确认或 S5 重置后必须完成一次写作要求交互，才会进入原有关系规划、依赖调度、Writer 和 Reviewer 链路。“没有特殊要求，直接开始”仍会形成默认计划，但不增加第二次确认。

写作计划磁盘格式和确认目录哈希成为 S5 执行输入；缺失、损坏、目录不匹配或叶节预算不闭合都会阻止启动。S5 明确重置会删除 `chapters`，因此也删除询问标记和计划并重新询问；执行失败后的普通重试复用同一确认计划。

等待门禁及 S5 运行期间客户端开放普通消息；完成后的无引用消息进入整体计划调整，有章节引用的消息仍沿原 Writer 修订。运行中收到新要求时，Host 先排空持有项目锁的旧计划操作再让 Main Agent 处理消息。
