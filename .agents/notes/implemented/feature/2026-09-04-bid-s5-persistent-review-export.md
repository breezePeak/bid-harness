# Agent Note: S5 常驻审核与按需 Word 导出

Status: implemented

## Problem

章节写作完成后，线性阶段自动进入 `docx_export`，客户端随即隐藏 S5 审核项。用户无法在完整章节和 Reviewer 状态旁复核内容，也不能从审核工作台重复生成 Word；导出行为错误地决定了写作审核页面是否存在。

## Decision

线性工作流在 `chapter_writing/completed` 结束，Host Projection 此时开放 `export_docx`。审核项从 S5 开始常驻，完成后保留逐章写作和 Reviewer 状态；[审核结果投影](../bug-fix/2026-09-09-bid-s5-review-result-projection.md)读取当前章节产物显示详情和执行失败原因。工作台通过独立 `bid/exportDocx` Remote 按需导出，每次在输出目录生成带时间标识的 Markdown 和 DOCX 文件。导出持有项目锁并重新校验确认目录、章节集合和 DOCX 产物，不修改 S5 状态。已保存为 `docx_export/completed` 的项目投影同样开放审核和导出，以便现有项目继续使用。

正文工作台的“导出 Word”入口只打开同级配置页。`word-export/config.json` 保存项目级格式、字段覆盖、候选映射和成功文件引用，模板按内容摘要独立保存；会话接管不复制聊天，也不自动执行 S6。配置版本拒绝过期编辑，正文、图片及生效值共同标识预览与交付版本。模板解析直接读取有界 DOCX XML，实际使用的命名标题和正文样式按继承结果提取，未明确角色的段落另保留直接格式候选；局部文字格式不改变段落用途。首行缩进保留字符或毫米单位，颜色和正斜体由同一生效配置控制；继承链未声明段前、段后间距时按零处理。生成器把标题的生效格式同时写入段落和样式定义，避免编辑器继承生成库自带的主题。解析缓存按提取规则版本保存，重新上传会刷新旧规则的结果。不明确的用途由用户映射或单次模型建议辅助确认；生成按钮旁列出待确认角色，用户可明确选择默认方案。生成器只排版已确认内容，模板旧正文、批注和项目文字不进入输出。

自然语言建议通过现有 LLM 服务调用，完整输入记录为 `bid.word-format.request`，不进入普通对话历史。模型只能建议有用户原话依据的字段或引用程序给出的候选；应用操作仍由用户确认。模型失败不妨碍手动配置。浏览器预览与 Word 使用同一遍历器和生效配置，明确提示分页以 Word 为准；缺失内容的样例只进入预览。正文工作台从已生成的导出内容快照估算页数，父节点汇总自身和后代而全文按文档顺序只计一次；未生成内容不预测，格式、内容或图片变化使项目级缓存失效，估算失败仅在页数区域显示不可用。

## Alternatives considered

**导出后继续停留在 `docx_export`，仅让前端伪装成 S5。** 这会让 Host 状态仍把导出误作章节写作的后继阶段，新 Session、准入和其他客户端仍会看到错误的线性关系。

**在运行状态中增加第二套 S6 子状态。** 当前需求只需要可重复导出及结果路径；独立子状态会增加 Session Event、项目格式和 SDK 投影改动，却不改善导出准入或章节审查。

**提取模板纯文本后交给模型重建格式。** 纯文本丢失字号、继承、编号及页面信息，模型无法准确恢复；格式数值由程序读取，语义建议不拥有文件路径或写入能力。

## Consequences

S5 完成状态和章节检查点保持稳定，导出失败不会遮蔽审核工作台，也不会要求重跑章节。每次导出使用独立文件名，已打开的旧 Word 文件不会阻止新导出；输出目录会保留用户主动生成的多个版本。`docx_export` 阶段类型暂时保留，用于读取既有项目状态和底层导出任务，但新流程不再自动进入该阶段。各阶段的入口名称和确认位置遵循[累积详情规则](2026-09-07-bid-persistent-details.md)。

首版不复刻复杂封面、Logo、浮动对象或多分节版式，也不接入 Word 分页引擎；估算保留未取整页面占用，只在章节或全文汇总后向上取整，因此章节显示之和不要求等于全文。标题使用[原生多级编号](2026-09-08-word-native-heading-numbering.md)，可在 Word 中继续编辑并生成目录。项目外图片和不支持的 Markdown 节点明确报错，不静默丢弃。源码 Loader 回放覆盖配置恢复、预览不生成文件及显式导出；包测试检查 XML 格式、内容保留和危险模板拒绝，页面测试覆盖建议确认及失败后保留下载。
