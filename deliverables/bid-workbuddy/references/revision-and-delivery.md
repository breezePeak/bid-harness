# 变更、恢复与交付规则

本文供 WorkBuddy 处理全书标书的后续改稿、任务中断及文件交付时查阅。业务资料与写作规则见[全书读标、研究与写作规则](domain-workflow.md)；实际命令、数据格式及可用工具以技能入口为准。

## 保存可继续的工作结果

长任务以实际文件中的资料清单、响应矩阵、章节答题卡、正文、问题清单和交付清单为继续工作的依据。会话摘要用于帮助定位，不替代原文件、原始要求和证据。保存采用当前环境的文件或文档能力；没有文件写入能力时，明确说明只能提供当前会话结果，不能承诺持久恢复。

在读标结果形成、章节正文完成、审查结束或批量修改前后保存进展。记录已完成内容、未解决问题、正在处理的对象及下一项可执行动作；不要只写“完成 80%”而缺少可核对的成果。

保留原始招标资料、用户原稿和已交付版本。修改生成新的草稿或使用工具提供的版本历史；只有明确授权覆盖时才替换原文件。临时文件、候选稿和正式交付物清楚区分，未验证的文件不能覆盖唯一可用版本。

完成状态以保存成功且重新读取可核对的结果为准。工具超时、返回不明或会话中断时，先检查目标文件和实际内容，再决定补做；避免重复生成相同章节或把已成功的操作再执行一次。

## 接受用户变更

从真实用户请求提取修改对象、目标、必须保留内容、允许改变的范围以及验收条件。结合此前仍适用的授权执行，不把模型自行概括的“优化”扩展为删除、重构全书或改变商务承诺的权限。

能够明确定位的局部修改直接执行。存在两种互斥业务解释、改变中标相关硬承诺、需要删除用户指定原文、需要采用未授权报价，或无法定位实际修改对象时，集中提出必要问题，同时继续不受影响的工作。

| 变更类型 | 先核对什么 | 必须跟随更新的内容 |
|---|---|---|
| 招标补遗、答疑或需求更新 | 文件真实性、适用标包、变动原文与已有要求的关系 | 响应矩阵、评分响应点、相关章节职责、依据和正文审查 |
| 新增企业材料或公开技术依据 | 材料主体、有效期、版本、适用场景及原缺口 | 对应答题卡、相关事实表述、引用与问题状态 |
| 目录拆分、合并、移动或删节 | 业务归属、现有正文、图表、强制要求的承接位置 | 目录、内容分配、响应位置、跨章引用及受影响审查 |
| 修改章节正文 | 目标段落或表格、用户意见、需要保留的内容 | 该处正文、事实依据及实际受到影响的其他位置 |
| 调整模板、版式或页数目标 | 招标格式要求、用户偏好和当前内容长度 | 样式、目录、分页、图表布局及最终渲染检查 |
| 修改商务承诺或报价 | 明确授权、真实数值、计价口径及关联条款 | 商务矩阵、报价表、正文中的相同承诺和全部汇总 |

材料变化不总需要重写正文。先判断原表述是否仍受支持；只有证据位置变化时可更新引用并复核，方案决策变化才处理相关内容。新章不自动使其他已完成章失效，共用背景也不意味着全书都需重写。

审批意见必须对应当前版本。旧意见引用的文字已经改变时，重新定位其真实对象；不能盲目按旧段落序号执行。保留每条意见的处理动作、结果位置和未解决原因，不能仅以“已处理”结案。

## 调整目录与保留原文

拆章或合章前保存源正文和可恢复版本，识别完整段落、列表、表格、表题、图片及其引用。让模型判断内容归属，由当前可用程序或文档工具执行移动与组合。需要逐字保留时，从原文直接迁移，不让模型重新抄写。

核对每个来源内容是否有明确去向，表题与表格、图与说明、引用与目标保持配套。只在用户允许时删减或复制原文，不能以“避免重复”为由删掉独有事实或证明。正式文件中的原文与新增段落分别核对，避免对新内容的修订破坏保留要求。

拥有可执行差异工具时，对比修改前后正文、表格、图表数量及保留内容；需要逐字保证时使用程序逐字比较。没有这样的工具时只能记录人工或模型阅读核对，不能声称机械证明完整。对无法可靠迁移的复杂浮动对象或嵌入文件保留原件，并报告需要人工处理的位置。

内容迁入新章节后检查新位置的标题、上下文、交接关系和评分归属。原文完整保留与新章节职责可能冲突，此时说明冲突并在授权范围内调整周围新增内容；没有删除或改写授权时保留原文并请求必要决定。

## 中断、失败与继续

继续任务时读取实际成果和最新用户要求，确认使用的招标版本、目录、材料及正文仍对应当前任务。检查完成标记与实际文件是否一致；已有正文但尚未审查时，从审查继续，不能把“有文件”误认为已完成。

| 情况 | 继续方式 |
|---|---|
| 搜索或网页读取失败 | 记录失败来源和需要核实的事项，采用合法可访问替代来源，继续其他研究；未核实结论不转为事实。 |
| 模型或文档工具临时失败 | 先检查保存结果，再对未完成动作作有限重试；连续相同失败时切换实际可用方式或报告具体阻塞。 |
| 缺少企业证明或必要业务参数 | 保留完成部分，集中列出必须补充的文件或决定；其他独立章节继续。 |
| 正文已完成、审核未完成 | 读取当前正文与证据，只补审核及必要修订。 |
| 文档导出失败 | 保留正文及中间格式，查明导出能力或输入问题，再重试导出，不重复写书。 |
| 恢复时发现资料或正文已经变化 | 定位变化及其关联事项，仅重做失效部分，旧审核结论保留为历史记录。 |
| 文件损坏或来源无法对应 | 保留损坏原件和现有备份，停止依赖该文件的写入；不能让模型猜测原内容修复。 |

用户说“继续”时延续已授权任务，不另建不相关目标。用户明确停止时先保存已产生的结果和剩余事项，并停止新的工作；以后恢复按真实文件继续。工具或模型的重试次数不等于业务质量已经达到要求。

## Word 组成与格式

优先使用用户指定模板和当前环境实际可用的文档能力。先检查模板中要求的页面、字体、标题层级、编号、页眉页脚、目录、表格和签章留位，再映射正文。格式模板内的旧项目名称、旧声明和旧附件不能自动成为本项目内容。

使用文档结构与样式生成标题和目录，使后续修改能够更新。全书按确认目录组合正文，检查标题层级、表格标题、图号、交叉引用及附件对应关系。图片或流程图的格式选择取决于当前工具和用户要求，不假定一定有 Word、Visio、LibreOffice 或特定导出插件。

用户要求可编辑图表时，确认输出文件实际包含可编辑对象；只有图片时如实说明限制。图表必须清楚可读、文字完整、连接关系正确并且不越出页面。复杂表格核对列宽、重复表头、合并单元格、跨页断行和注释，不能只验证文档能够打开。

页数要求优先服从采购文件，其次服从用户明确目标。页数以实际排版后的文件为准，篇幅估算应标明估算。短于目标时优先补足缺失的措施、依据、职责和成果；不得用重复段落、无关背景、异常字体或空白页凑页数。

能力允许时渲染或用文档应用打开最终文件，检查封面、目录、各级标题、典型正文、全部复杂图表、横向页面及文件末尾；短文档可逐页检查，长文档按结构与风险检查，并明确检查范围。只做文本抽取或文件结构检查时，不能宣称已完成视觉排版验收。

每次对影响分页的正文或样式进行修改后，更新目录和交叉引用并复查受影响页面。工具不能更新域或页码时，明确提示需在相应文档应用中更新，不手工写入未经验证的页码。

## 全书核对与交付

交付前把最新正文、响应矩阵、资料清单和问题清单相互核对。审查版本必须对应实际交付文件，不能用较早草稿的通过结论覆盖之后的改动。

| 核对对象 | 需要可观察的结果 |
|---|---|
| 需求与评分 | 每个适用事项有实际响应位置，重点评分情境有具体措施或成果，缺项明确列出。 |
| 事实与承诺 | 企业主体、案例、人员、产品参数、标准版本、数量、时间和价格有适用依据或明确授权。 |
| 全书一致性 | 项目名称、简称、接口、角色、工期、里程碑、指标和商务承诺在各处一致。 |
| 商务与资格 | 必需证明实际存在，适用主体与有效期已核对，签字盖章和待提供材料明确登记。 |
| 报价 | 授权数值、单位、含税口径、公式、舍入和汇总相符；未核准的报价不视为最终报价。 |
| 文件与版式 | 交付文件可打开，结构完整，图表与引用相符，完成了与当前工具能力对应的格式检查。 |
| 递交条件 | 格式、大小、份数、命名、签章、加密和渠道要求已有核对结果，实际递交另行记录。 |

交付包包含用户要求的正文文件、必要附件或明确的附件缺口、可定位的响应矩阵、剩余问题与人工确认清单。研究账本和内部审核记录作为工作材料保存，不把内部标识、待办指令、技术日志或未经核实的事实混入客户正文。

区分文件生成成功、内容审查完成和可提交状态。关键事实未补齐、强制响应缺失、报价未核准或必要签章未完成时，可以交付标明状态的草稿，同时列明具体缺口；不能宣称它已可正式递交。少量非阻断建议也应记录，是否采纳尊重用户目标。

最终回复说明已生成文件、覆盖范围、实际执行的检查、未完成项及下一步责任人。没有运行的脚本、没有完成的视觉复查、无法访问的来源都要如实说明，不以存在模板或清单代替实际验证。

## 人工决策与最终递交

项目负责人或其他获授权人员核准企业事实、人员投入、合同偏离、交付承诺及最终报价；采购规则和合同效力存在争议时，由有职责的人员审定。WorkBuddy 可以整理证据、比对要求和提出修改，但不代替这些确认。

签名、盖章、付款、投标平台上传及最终递交按用户明确授权和平台权限处理。普通“写一份标书”不意味着授权作出上述外部行为。用户已明确授权的可执行动作按其范围完成，并保存实际结果；未执行或失败的递交不能记为成功。

在最终递交前保留可恢复的定稿及交付清单，记录实际使用的文件版本。递交后的内容修改应产生新的版本并由负责人员判断是否允许替换，不能静默改变已递交文件。
