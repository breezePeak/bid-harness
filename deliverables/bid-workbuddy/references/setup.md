# 在 WorkBuddy 中准备标书工作区

本教程用于首次导入本技能、检查工具和建立独立标书目录。技能脚本需要 Python 3.10 及以上；来源登记与流程编排只使用标准库，DOCX 导出需要 `python-docx`，图片处理需要 `Pillow`。

## 1. 导入独立技能包

通过当前 WorkBuddy 版本提供的本地技能包导入功能导入交付包。导入后确认 WorkBuddy 能读取技能根目录的 `SKILL.md`，以及其下的 `scripts/` 和 `references/`；不要只导入一个说明文件。

本技能使用 `bid-workbuddy` 名称，可与 `bid-writing-workflow` 并存。已有同名技能时先确认其来源和内容，不直接覆盖；更新本技能前保留旧包。不要把脚本或项目资料解压到另一技能的同名目录中。

在 WorkBuddy 中指定本技能，要求它先读取 `SKILL.md` 并检查实际可用的工具。技能文件中的名称不会创建搜索、网页读取、Shell、文档或 OCR 工具。

## 2. 选择实际 Python 解释器

优先使用 WorkBuddy 已配置、允许执行脚本的 Python。检查版本和可执行文件路径，确认后对本项目始终使用同一个解释器。不要只凭 `python` 命令存在就认为环境已准备好；办公软件附带的内嵌 Python 可能不能启动子进程或使用所需依赖。

在 Windows PowerShell 中可先用 `Get-Command python, python3, py -ErrorAction SilentlyContinue` 查看候选位置。下面的路径均须换成实际路径，再执行检查：

```powershell
$BidPython = 'C:\实际路径\python.exe'
$BidSkill = 'D:\技能目录\bid-workbuddy'
& $BidPython "$BidSkill\scripts\doctor.py" --json
```

在 macOS 或 Linux 中，用实际解释器路径执行同一脚本：

```sh
/实际路径/python3 /技能目录/bid-workbuddy/scripts/doctor.py --json
```

检查器会报告解释器、`python-docx`、`Pillow` 和可选 Word 兼容 COM 注册、LibreOffice、PDF 页面渲染命令的发现结果。它不会启动 Office 或 LibreOffice，不会安装依赖。`Word.Application` 注册也可能由 WPS 提供，不证明安装了 Microsoft Word 或能够转换 PDF；PATH 中发现渲染命令也不等于实际渲染成功。

退出码 `0` 表示完整依赖可发现；`1` 表示仍有条件缺失；`2` 表示命令参数错误。缺少 `python-docx` 时，流程编排和来源校验仍可用，DOCX 导出不可用；缺少 `Pillow` 时，图片处理条件不完整。先说明缺少什么、影响哪一步和拟使用的解释器，获得用户安装授权后才能安装。不得静默运行安装命令、改变全局 Python 或重建项目依赖。

## 3. 确认 WorkBuddy 的资料工具

先查看当前会话真实提供的搜索、网页读取、文件读取、文档解析和 OCR 能力，并按工具自己的参数调用；不要照抄其他 Agent 的工具名称。网页检索命中后必须打开来源正文，记录用途、来源地址和实际阅读范围。搜索摘要、模型记忆和仅有 URL 的列表不能登记为已读取的网页正文。

PDF、Word、Excel、图片和扫描件由 WorkBuddy 已有工具读取或提取；本技能不会随包提供 OCR 或二进制文档解析器。读取失败、缺页、乱码、扫描页未经识别时保留原件并记录缺口，不把文件名或搜索摘要当作资料内容。将实际提取的文字保存为 UTF-8 文件，再用 `sources.py add` 的 `--text` 指定该文件，同时通过 `--file` 保留原件。

Web 来源使用 `--role web`，必须有 `--url` 和实际读取后保存的正文文件。来源脚本只校验所提交内容的完整性与后续引用一致性，不能证明 WorkBuddy 真的访问过该网页，也不能判断正文是否真实或支持某项承诺；这些事项需要研究与审核步骤核对。

若搜索工具缺失，明确报告尚未执行外部研究。已有本地资料足够时可以继续，并说明依据范围；资料不足时登记具体缺口，向用户说明需要提供的资料或可启用的搜索能力。不能生成虚构来源，也不能把待补资料标记为已核验。只有搜索但不能读取正文时，检索命中仍是候选来源。

## 4. 建立独立项目目录

为每份标书选择独立目录，例如 `D:\投标项目\项目名称-workbuddy`，并让 WorkBuddy 确认当前工作目录。技能安装目录只保存技能本身；上传原件、登记快照、阶段候选、审核记录和输出文件保存在项目工作目录中。

不要把项目工作目录指向已有 Bid Harness 的 `.bid-harness`、另一份标书的工作区或 `bid-writing-workflow` 的既有产物目录。本技能与旧项目并存，不读取或改写旧项目的正式流程状态；要复用旧标，按资料导入原件。用户未明确要求覆盖时，已有同名交付文件保留，另存新版本。

按 `SKILL.md` 启动项目后，先用一份招标文件完成来源登记和分行读取，确认回执包含程序生成的来源位置与真实正文，再进入分析。资料登记只允许单写入者；同一来源的新版本会作为新条目追加，旧引用继续指向原快照。
