# Word 导出参考

导出器读取工作区 `build/book.json`，生成可编辑的 DOCX。工作区存在 `project.json` 时，导出前会重新编排并核验当前项目，拒绝复用过期的 ready 文件。运行环境需要 Python 3.10 及以上和已安装的 `python-docx`；缺少依赖时报告缺少的模块，未经用户授权不安装。目录和页码由 Word 或 LibreOffice 的排版引擎计算，脚本不填写假页码。

## 命令

```shell
python scripts/export_word.py WORKSPACE --output WORKSPACE/output/技术标.docx
python scripts/export_word.py WORKSPACE --output WORKSPACE/output/技术标.docx --template 模板.docx --profile 排版.json
python scripts/export_word.py WORKSPACE --output WORKSPACE/output/技术标草稿.docx --draft
```

正式导出要求 `book.status=ready`；`--draft` 允许导出未完成审核的正文，并在生成内容前显示“草稿 未完成正式交付审核”。文件只有在所有输入和正文解析成功后才原子替换；格式错误不会覆盖已有成品。脚本成功仅表示已生成文件，不代表事实审核、目录更新或视觉验收已经完成。

## 正文输入

`book.json` 由工作流程序生成。`title` 是用户确认的非空标题；`bidder`、`date` 为投标单位和日期文字，未知时使用空字符串，封面会略过，不能虚构。`issues` 为问题数组；`sections` 按交付顺序排列，每项包含 `title`、`number`、`level`、`body`。`body` 是 Markdown 字符串，不是文件路径。`level` 从 1 开始，不能跳级且最大为 6；程序核对 `number` 是否符合目录顺序，例如 `1`、`1.1`、`1.2`、`2`，不让模型补写目录身份。

没有 `project.json` 时，独立 `book.json` 仅作为外部程序和结构测试的低层输入；导出器无法据此重建审核过程。正式工作必须使用完整项目工作区，不能移走项目状态文件来绕过检查。

| 正文元素 | 支持方式 |
| --- | --- |
| 段落 | 空行分段，普通单换行作为同一段落 |
| 强调 | `**粗体**`、`*斜体*`，不支持嵌套强调 |
| 列表 | `-`、`+`、`*` 或 `1.`、`1)`；两个空格一级，最多六级，同一嵌套列表保持同一类型；有序列表须连续，子列表从 1 开始 |
| 子标题 | 叶节正文的 `#` 是该节下一层，`##` 再下一层；总层级最多六级，程序生成完整编号；含正式下级目录的父节正文不能另建标题 |
| 表格 | 每行使用首尾 `|`，第二行为 `---` 分隔行，列数一致；支持 `:---`、`:---:`、`---:` 对齐，`\|` 表示单元格内竖线 |
| 表题 | 表格紧前一行写 `表：责任分工`，程序生成表号；未指定时使用“表 1”等基本题注 |
| 图片 | 独立一行 `![实施流程](assets/流程.png)`，图片适配可用页宽和页高，说明文字形成带编号图题及替代文字 |
| 超链接 | `[资料标题](https://example.com/source)`；支持 HTTP、HTTPS 和邮件链接，不自动访问 |

图片必须已保存在工作区内，允许 PNG、JPEG、BMP、GIF、TIFF；导出使用静态图。拒绝外网图片 URL、绝对路径、越界路径和指向工作区外的链接。SVG、Mermaid、数学公式等应先经独立程序生成并检查本地 PNG，再引用图片；不能假装已导出可编辑矢量图或公式。

代码块、内联代码、HTML、引用块、脚注、引用式链接、任务复选框、删除线、Setext 标题、下划线强调、制表符缩进、两个空格或反斜线产生的硬换行等不在支持范围内，遇到会报错。把内容转换为已支持格式后重试，不删除业务内容来消除错误。复杂合并表格、多栏布局、浮动图和跨页签字区应使用明确设计的模板或在 Word 内完成。

## 默认排版与配置

无模板时生成 A4 纵向文档、封面、真实 TOC 域、一级至六级标题、页脚 PAGE 域；封面不显示页码，正文和目录的页码按文件实际页序连续计算。正文默认宋体 12 磅、1.5 倍行距，标题黑体且为黑色。表格按内容长度分配列宽、允许单元格换行，重复表头；图片保持纵横比，不放大超过原图物理尺寸。表号和图号由程序按正文顺序生成。

```json
{
  "body_font": "宋体",
  "heading_font": "黑体",
  "body_size_pt": 12,
  "line_spacing": 1.5,
  "margin_top_cm": 2.5,
  "margin_bottom_cm": 2.5,
  "margin_left_cm": 2.8,
  "margin_right_cm": 2.5,
  "toc_levels": 3
}
```

字号允许 9 至 24 磅，行距 1 至 3 倍，边距 1 至 5 厘米，目录层级 1 至 6。未知参数拒绝；不能以配置声明已完成审核、指定虚构页码或伪造页数。字体需要在实际排版机器上可用，否则 Word 或 LibreOffice 可能替换字体并改变分页。

## 用户模板

模板必须是可读取的单栏 `.docx`，在正文顶层含唯一独立段落 `{{正文}}`。导出器在该位置插入正文并移除锚点，保留锚点之外的原文、表格、页眉页脚与页面设置；输出路径不能覆盖原模板。模板原有 TOC 域必须启用大纲级别选项，即含 `\u` 开关，导出器保留该目录且不重复插入；没有 TOC 时在锚点处插入目录。排版配置只设置插入内容使用的专用样式，模板页边距和纸张以模板为准。

模板任一节采用多栏布局都会拒绝，避免按整页宽度生成的表格或图片越过栏宽。仅按自定义样式收集条目、未启用大纲级别的原有目录也会拒绝；请先在 Word 的目录选项中启用大纲级别，保留其他设置后重试。导出器不改写模板原有目录指令。

表格或文本框里的锚点、多个锚点、带其他文字的锚点、与分节符放在同一段的锚点都会诊断退出。已含 `Bid Body`、`Bid Heading 1` 等导出专用样式的模板也会拒绝，避免修改这些样式时改变模板已有正文；应使用原始模板。模板里的封面资料、签章区、专用目录样式和页码重启规则需要事先正确设置。程序不猜测占位位置，不清空未知模板，不承诺任意模板的完整保真。

扫描版模板须先完成 OCR 与人工核对；电子签名、印章、资格文件有效性与最终上传递交需要真实授权和材料，不能由模型或脚本生成假证明。

## 交付验收

1. 在 Word 中更新全部字段，对目录选择“更新整个目录”；LibreOffice 使用“工具 → 更新 → 全部更新”。核对目录条目、层级、页码和页脚是否与实际正文相符，保存更新后的 DOCX。
2. 使用可用的文档渲染工具将保存后的文件导出为 PDF 或逐页图片，逐页检查中文字形、标题分页、表格跨页、重复表头、图片清晰度、题注和模板原有内容。可以使用所在运行环境提供的 `render_docx.py`，但不能仅凭 OOXML 检查宣称版式合格。
3. 在实际提交软件上打开最终文件，核对招标方要求的目录、页面、签章和附件。要求 PDF 时，从字段已更新且完成视觉检查的 Word 文件导出，检查 PDF 后再交付。

没有可用的渲染器时保留 DOCX 并明确标记“视觉验收未完成”，不能把文件生成成功当作最终排版通过。页数指标必须使用实际排版结果，不按字数推测后宣称满足。
